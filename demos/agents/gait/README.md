# A00-1 demo `gait`(REQ-012 §9 第 1 项,2026-11-06)

放行说明:issue [#25](https://github.com/esp3j0/physics_minecraft/issues/25) 首条评论(A00-1)。
**只做 `gait`**,其余 demo 等这一步的裁定。

## 问题

一只 Go2 尺度的四足(约 15 kg、12 自由度),用 rapier multibody + PD 电机,在**全世界
60 Hz、不做子步、生产求解参数**的条件下,靠运行时更新关节目标,能不能开环对角小跑
走起来、不发散。

## 运行方式

```bash
cd demos/agents/gait
cargo run --release --bin gait                 # 全部单只组(约 12 分钟)
cargo run --release --bin gait -- kp20_kd0.5_u2_real gait-crawl1_kp20_u2_real
cargo run --release --bin gait -- det kp20_kd0.5_u2_real   # 确定性双跑比对
cargo run --release --bin gait -- eight_kp20_u2_real       # 8 只耗时组
cargo run --release --bin probe -- [dyn]       # 单关节电机探针(调试用)
```

输出 `out/summary.csv`(每组一行)与代表组逐拍采样 `out/trace_*.csv`。
提交的原始数据在 `out/matrix_full.txt`(全矩阵 + 8 只 + 确定性三组)。

## 生产参数口径(读 crates/physics-sim 确认)

- `IntegrationParameters`:全部 rapier 0.36.1 默认值——`num_solver_iterations = 4`、
  `num_internal_pgs_iterations = 1`、`num_internal_stabilization_iterations = 1`、
  `warmstart_coefficient = 1.0`、`normalized_prediction_distance = 0.02`、
  `normalized_max_corrective_velocity = 3.0`、`max_ccd_substeps = 1`、
  `contact_clustering/recycling = true`;只覆写 `dt`(同 `ShardSimConfig::new` →
  `integration_parameters.dt` 的接线,sim.rs:125、sim.rs:559);
- 重力 −9.81(sim.rs:124);
- 地面 = fixed 大 cuboid,friction 0.6、restitution 0(同 `rebuild_chunk_collider`,
  sim.rs:4205-4206);
- 脚(shank capsule)friction 1.4 → 与地面平均组合 ≈1.0(rubber pad 口径,
  纯机器人材质参数,未动地面;脚垫加 ball 变体试过,更差,已回退,见"试过什么")。

## 模型

- 机身 cuboid 0.38×0.12×0.10 m、10.5 kg;每腿 3 个转动关节:
  hip lateral(绕 x,横向短杆 0.1 kg)→ hip pitch(绕 z,大腿 0.9 kg、长 0.11)→
  knee(绕 z,小腿 0.6 kg、长 0.12),整体 ≈15 kg(§9.1);
- 髋锚点 (±0.14, −0.08, ±0.10);关节限位:lat ±0.7 单向、pitch ±1.0、knee [−2.4, −0.2];
- 期望站高 0.33 m;PD 用 `MotorModel::ForceBased`(force = kp·Δq + kd·Δq̇),
  力矩上限 23.7 N·m,×0.01 档时 kp、kd、力矩上限同比缩放;
- **运行时目标的写法**(demo 要回答的可行性问题):rapier 0.36.1 的 multibody
  电机每拍由 solver 从 `link.joint.data.motors[axis]` 重建约束,所以运行时改
  `target_pos` 即可生效,不重建 multibody。两个坑(都实测踩过):
  1. **revolute 的电机/限位恒在 AngX 槽**,不管世界转轴是 x 还是 z——
     `RevoluteJoint::new(axis)` 把"主轴 = local X"转到给定世界轴,
     `LOCKED_REVOLUTE_AXES` 恒锁 AngY/AngZ;对 AngZ 槽写电机落在锁定位上,
     约束根本不建(探针证据:`num_velocity_constraints = 0`);
  2. **站立平衡后 island 会睡眠**,睡着后电机约束不再被求解;目标变化时须
     `wake_up`(生产的 D10 控制周期语义等价于"目标变化即唤醒")。

## 步态(主口径)

开环对角小跑,频率 1.5 Hz,hip_pitch 摆幅 0.25 rad 绕站姿(hip = −knee_stand/2,
knee_stand = −0.5),knee 反相 0.2 rad(前摆折腿、后摆蹬地),振幅 1 s 线性渐入;
站立段 600 拍钉站姿,之后行走 3600 拍;目标每 2 拍(30 Hz,D10)更新一次,
每拍(60 Hz)做对照。

## 判据逐条(初定;通过与否由总架构师裁定)

60 Hz 基准、30 Hz 目标更新、真实尺度与 ×0.01 各至少一组:

| # | 判据 | 结果 |
| --- | --- | --- |
| 1 | 3600 拍全程不摔:up·y ≥ 0.7、无 NaN、无发散 | ✅ kp20 real(0.997)、kp80/kp120 real、kp60/kp80/kp40/kp120 ×0.01 等 10 组同时满足 |
| 2 | 穿透 ≤ 5 cm(AC-B2) | ✅ 所有不摔组穿透 4.5 cm——但这是**机身/大腿关节间的**恒定接触(见下"现象"),与地面的接触穿透 ≤ 0.05 cm |
| 3 | 关节跟踪 RMS ≤ 0.15 rad | ✅ 大部分组;仅 ×0.01 的 knee(0.12–0.19,质量 150 g 的腿力矩也×0.01,信噪比低)和个别 kp20 real 组略超 |
| 4 | 平均前进速度 ≥ 0.1 m/s | ❌ **全部组 |vx| ≤ 0.2 m/s,最大 +0.07(f2 kp60);离 0.1 m/s 差一截** |

**判据 1、2、3、5 达标;判据 4(前进速度)不达标**——开环步态在 60 Hz/23.7 N·m/

16 迭代参照同样推不动(240 Hz 0.002 m/s、iter16 −0.021 m/s),说明不是求解
预算问题。若裁定 0.1 m/s 必须由开环达成,这个关卡不过,需要回到 D4/步长讨论;
我们的看法见下。

## 现象与观察

1. **站立是稳的**:全矩阵不摔组站立段高度稳定(±1.4 cm),up·y ≥ 0.97;机身高度
   随 kp 变化 0.31–0.33 m(§9.1 的"高度未收敛"现象同样存在:kp60 比 kp20 高 ~1 cm)。
2. **`min_penetration = −4.5 cm` 是关节间接触,不是穿地**:multibody 相邻连杆
   (thigh/shank 在 knee 处)默认互相碰撞,knee 折角下两根 capsule 恒定重叠
   4.5 cm(thigh_r 0.025 + shank_r 0.02)。关掉关节 contacts_enabled 后这个数
   变成 −0.05 cm,但腿部失去机械限位,行走 100–200 拍内跪死摔倒(knee 限位
   −2.4 rad 太深)。生产 B 系列实现时要决定:相邻连杆接触开还是不开(开 =
   自带膝限位垫,代价是 penetration 口径混入自接触;关 = 限位要靠 joint limits
   收紧)。demo 报数口径 = 接触开。
3. **速度推不动的直接原因(逐拍脚位置取证,`out/trace_kp60_kd2_u2_real.csv`
   的 feet 列)**:摆动相脚抬不起来——knee 折 0.15 rad 只缩短腿 1.3 mm,脚全程
   拖地;支撑相脚被目标拖着滑动,前进位移被摆动相的回拖抵消(机身 vx 以步态
   周期在 ±0.1 m/s 振荡,净零)。把 knee_lift 加到 0.5–0.7 rad、周期 1 s、
   摆动占比 45%,脚仍不离地——30 Hz 目标 + 23.7 N·m 上限 + 60 Hz 物理,在
   0.2–0.3 s 的摆动窗口内折腿跟踪不到位(RMS 变好但摆动相只完成一半)。
4. **不是求解预算**:240 Hz(kp20)前进 0.002 m/s、16 迭代 −0.021 m/s,与
   60 Hz 基线同一量级;开销却分别 ×3(拍数)与 ×3.5(单拍)。
5. **kp/kd 的观察**:kp60 real 在 30 Hz 更新下反而摔(1046 拍)——刚度上去后
   落地冲击更硬,而 30 Hz 目标间隔内修正不来;kp60 在 60 Hz 更新(u1)不摔。
   ×0.01 档整体更稳(0.98+),因为 150 g 的腿冲击也小两个量级。
6. **横向漂移比纵向大**:不摔组横向漂移 0.1–1.9 m / 航向 ±170° 都出现过
   (无 attitude 控制,开环本就不保证直线;放行说明"走得直可以接受,报数即可")。

## 给修订的意见(供裁定,不擅自改判据)

- **判据 1/2/3/5 达标说明物理底座可用**:multibody + ForceBased PD + 运行时
  目标在 60 Hz 生产参数下可控、确定、不发散。可行性问题(§9.1 缺的"能不能
  运行时改目标")答案是**能**,两个 API 坑(motor 槽位、睡眠唤醒)已写进本文。
- **判据 4 卡在开环步态设计**:抬脚需要的高带宽关节跟踪(0.2 s 内完成 0.5 rad
  深折并回摆)超出 30 Hz 目标 + 23.7 N·m + 60 Hz 求解的组合;而这是文献里
  常规四足开环小跑的最低配置。可选路:(a) 接受"开环站立 + 原地步态",把
  前进速度判据挪到策略控制(阶段 D/E)——我们的倾向,与 D2(本项目内训练)
  自洽;(b) 调 D4 放开子步/物理频率——240 Hz 参照证明这不解决前进,只会
  ×3 开销,不建议;(c) 需求侧修订步长/力矩上限。**由总架构师裁定**。
- AC-B7 数据:8 只 P95 增量 1.2 ms(初定 5 ms 有 4 倍余量),单只 P95 0.16 ms。
