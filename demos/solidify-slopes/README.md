# solidify-slopes:斜坡(阶梯)/堆叠慢爬行下的 P2 凝固触发参数验证

## 对应的架构问题

REQ-001 §9 决议 5 的欠账:**"斜坡/堆叠慢爬行 demo 在 REQ-002 定稿前补"**
(`docs/requirements/REQ-001-architecture.md` L276-277)。§4.3(L183)把凝固桥
触发定为 **P2:线速度 <0.1 且角速度 <0.05 连续 20 tick + 睡眠兜底**;demo C
(`demos/solidify-bridge/`)只覆盖了"平地硬停"场景(无慢爬行期,P2 与 P1 误差
逐位相同),并明确留有"斜坡/堆叠慢爬行场景未覆盖"的风险条目。

本 demo 回答两个问题:

1. 存在**持续的真实低速运动**(速度信号恒低于 P2 阈值)吗?P2 会把还在动的
   实体误判成静止吗?(误凝固风险)
2. 堆叠场景里,下层合法凝固后,上层会被错误凝固吗?

**结论先行:会。P2 现参数在受驱慢爬行/阶梯/滑行场景 100% 误凝固;堆叠场景
本身不误凝固;需要修订(位移门 + 政策层豁免),见文末建议。**

## 单位澄清(重要)

P2 阈值 0.1/0.05 的单位是 rapier 线/角速度 = **m/s、rad/s**(dt=1/60,0.1 m/s
≈ 每 tick 位移 1.67mm)。任务书写的"0.01-0.09 m/tick"若按字面是 0.6-5.4 m/s,
远高于阈值、永远不会触发 P2。本 demo 主扫描取 **0.02/0.05/0.08 m/s 三档**
(与阈值同单位,覆盖"恰低于阈值"的语义),另加一档**字面 0.09 m/tick =
5.4 m/s 对照**,证实该档无触发(最长连续慢速 run=1 tick)。

## 测量约定(诚实条款)

- **策略可见速度** = 每 tick `step()` 之后、下一次驱动之前读到的 `body.linvel`
  ——即凝固策略每 tick 真正会读到的信号(`run_sim`,`main.py`);
- **"持续低速运动"**用 P 控制器模拟:每 tick 末若 `vx < v_target`,补冲量
  `m·(v_target−vx)` 把线速度钉回目标——这正是 Minecraft 实体每 tick 被移动
  代码钉速度的物理对应(潜行/水中缓行);
- 同时报告**净爬行速度 = 位移/时间**,防止把 stick-slip 尖峰误当匀速。

## 场景与实测数据

### A 平地匀速缓行(P 控制器钉速,无摩擦面+线性阻尼 2.0,600 tick)

| 目标 m/s | 采样lin p50 | 净爬行 m/s | 最长连(lin∧ang) | 首触发tick | 首触发d20(m) | resid100(m) | d_final(m) | P2触发次数 | P2'(3mm门)次数 |
|---|---|---|---|---|---|---|---|---|---|
| 0.02 | 0.0194 | 0.0200 | **600** | 20 | 0.0063 | 0.0333 | 0.1933 | **30** | 0 |
| 0.05 | 0.0484 | 0.0499 | **600** | 20 | 0.0158 | 0.0833 | 0.4833 | **30** | 0 |
| 0.08 | 0.0774 | 0.0799 | **600** | 20 | 0.0253 | 0.1333 | 0.7733 | **30** | 0 |
| 5.40(=字面 0.09 m/tick) | 5.2258 | 5.3939 | 1 | - | - | - | - | 0 | 0 |

d20=触发时刻回看 20 tick 的位置位移;resid100=触发后 100 tick 若未凝固的实际
位移;d_final=触发位置到实验结束时最终位置的距离(= 若当时真凝固会被吞掉的运动)。

**解读**:三档受驱爬行全程净位移 0.20/0.50/0.80 m,驱动 600 tick 不间断,
"连续低于阈值"最大 run = 600 tick(远超 20)。若按 P2 执行,每 20 tick 误凝固
一次(600 tick 触发 30 次),第一次就把还在走的实体冻成方块,d_final 达
0.19-0.77 m。**慢爬行场景 P2 必误凝固,无一幸免。**

### B 滚动球缓行(r=0.5,μ=0.5,钉速 0.08 m/s)

采样 lin p50=0.0800(ang p50=0.1600≈v/r),**0 触发**:滚动体的角速度信号
(0.16 rad/s)远高于 P2 角阈值 0.05,**角速度项有效保护纯滚动实体**。

### C 低摩擦惯性滑行(μ=0.01,初速 0.09 m/s,无持续驱动 = 滑行中的掉落物)

- 引擎睡眠阈值(实测读出):linear=0.05,angular=0.5,time_until_sleep=0.5s;
- P2 首次触发 @tick **20**(采样 lin=0.0573——实体还在滑!),此时距最终静止位
  d_final=0.0082 m——**把滑行中的掉落物提前 0.008 m 冻住**;
- 引擎 is_sleeping 首次 @tick 31(watch 模式不真凝固,实体靠摩擦自然滑停:
  库仑模型应滑 0.0413 m,实测 0.0312 m,差额为求解器数值耗散)。
- 冻结损失绝对值小,但**机制上 P2 和睡眠兜底都会截断滑行**;掉落物若在被
  捡取前滑动,行为改变是可感知的。

### E 堆叠(下层静止于地面,上层从 0.6 m 间隙落到下层,600 tick)

watch(只计数):

| 场景 | 层 | 首触发tick | 触发时高出预期静止位 | 触发前20tick均速/max | 触发后100tick位移 | 终点y(预期) |
|---|---|---|---|---|---|---|
| 2 层 | L0 | 20 | −0.1 mm(已落定) | 0.000063 / 0.0005 | 2.0 mm | 0.4999 (0.50) |
| 2 层 | L1 | 49 | −0.6 mm(已落定) | 0.0059 / 0.0303 | 0.04 mm | 1.4993 (1.50) |
| 3 层 | L0 | 20 | −0.1 mm | 0.000063 / 0.0005 | 1.2 mm | 0.4998 (0.50) |
| 3 层 | L1 | 82 | −1.2 mm | 0.0208 / 0.0743 | 0.13 mm | 1.4987 (1.50) |
| 3 层 | L2 | 87 | −1.7 mm | 0.0198 / 0.0747 | 0.12 mm | 2.4982 (2.50) |

- **无错误凝固**:各层触发都发生在冲击沉降结束之后(上层触发时已比预期静止
  位低 0.1-1.7 mm,即已坐实),触发后残余位移 ≤0.13 mm——上层从 0.6 m 间隙
  落地到进入 P2 计数(触发前 20 tick 均速已降到 0.006-0.021 m/s)总共只用
  49-87 tick,沉降段本身(<25 tick,见实测 L1 下穿 0.1 m/s @tick 25)不会被
  P2 中途截断成悬空凝固;
- **上层慢沉速度分布**:触发前 20 tick 均速 0.006-0.021 m/s、峰值 0.03-0.075
  m/s——低于 P2 线阈值,说明"沉降残余速度"天然满足 P2(这正是合法凝固的
  信号,不是误凝固);3 层堆叠的传递沉降(下层被上层冲击,lin p99=0.06-0.10、
  max 0.10-0.14)把 L1/L2 首触发推后到 82/87 tick,即冲击段保护了计数清零;
- **bridge 模式(下层 @20 真执行凝固桥)**:桥 snap 位移 0.1 mm、角度误差 0°、
  写入体素格 (0,0,0);上层 L1 正常落到凝固块上(终点 y=1.4999,底面 − 块顶
  = **−0.1 mm,零穿模**),L1 自己在 @42 合法触发,resid100=0.012 mm——
  **下层凝固不干扰上层物理,也不错误拖走上层**。

### F 对照:真静止实体 600 tick(demo C 完整流程)

P2 首触发 @tick **20**(期望值,桥正向工作);桥 snap 位移 0.070 mm、角度误差
0°;凝固后掉球验证 600 tick:末 100 tick 均速 0.0000 m/s、陷入块顶 0.161 mm
(容差 10 mm)、有限性 OK —— **PASS**。

### G 探针:Python 绑定侧收紧引擎睡眠阈值

对 `body.activation.linear_threshold` 赋 0.01 **不抛异常但被静默忽略**(回读仍
0.0500,睡眠行为不变,实测 is_sleeping 首次 @31 与默认一致)。→ 想把睡眠兜底
收紧到 P2 之下,必须走 Rust 侧配置。

### H 探针:睡眠兜底对"被驱动实体"是否兜得住

0.02 m/s 缓爬(低于引擎睡眠线阈值 0.05):驱动冲量 `wake_up=True` 时
**600 tick 内从未睡眠**(每 tick 驱动都唤醒)——P2 误触发后没有睡眠兜底
"纠正"的机会,反而 P2 触发才是唯一会执行的动作;`wake_up=False` 时兜底在
tick 31 生效。→ 对持续受驱实体,"P2+睡眠兜底"中的兜底是空转的。

### P2′(候选修订)同步验证

在所有场景中并行模拟 P2′ = P2 ∧ 最近 20 tick 位移 ≤ **3 mm**
(阈值取法:合法落定实测 d20 ≤1.4 mm,受驱爬行 d20 ≥6.3 mm,两侧各留 ≥2× 裕度):

- A/B 平地爬行与滚动:**挡掉 100% 误触发**(P2 90 次 → P2′ 0 次);
- C 滑行:首触发从 tick 20 推迟到 tick 65(实体已近滑停);
- D 阶梯:5/6 配置全挡住;1:4 @0.09 泄漏 29 次——实体顶在级缘真的停住
  (d20 低至 0.0004 m),**速度+位移信号无法区分"真停住"与"被驱动但暂时
  顶住"**,这是信号层面的根本极限;
- E/F 合法凝固不受影响:真静止对照仍 @tick 20 触发,L0 仍 @tick 20。

## 结论

1. **P2 现参数在慢爬行场景必然误凝固**:平地受驱 0.02/0.05/0.08 m/s 三档,
   "连续 lin<0.1 且 ang<0.05" 达 600 tick,首触发全在 tick 20,每 20 tick 复发;
   阶梯下行 6/6 配置在爬行早期(tick 20)误触发、全部早于级缘翻落;滑行掉落物
   在滑行中(tick 20)被冻,距最终静止位还差 8 mm。误凝固不是边缘情况,是
   受驱慢运动的**默认结局**。
2. **角速度项(0.05)有效保护滚动体**(滚动 ω≈2v,0.08 m/s 滚动球 ω=0.16),
   但对平动爬行无保护(爬行 ang≈0)。
3. **堆叠不产生误凝固**:下层触发是真静止(触发后残余位移 ≤2 mm),上层沉降
   在触发前已完成(触发时已比最终位低 0.1-1.7 mm、触发后 100 tick 只动
   ≤0.13 mm),下层真凝固后上层落定零穿模(−0.1 mm)且自己照常触发。
   demo C 担心的"堆叠慢爬行误凝固"未复现——沉降太快(<1.1 s),P2 的 20 tick
   窗赶不上沉降段。
4. **决议 5 的"睡眠兜底"对持续受驱实体是空转的**(wake_up 驱动永不完全睡眠),
   且睡眠阈值 Python 侧不可配置(静默忽略)。

## 参数修订建议(需走 REQ-001 §9 修订流程)

1. **政策层豁免(必要)**:凡当前有活动移动命令的实体(演员集:玩家/怪物/
   被红石推动的实体等)**不适用自动凝固**,凝固只由显式命令或命令结束事件
   触发。依据:顶在级缘的受驱实体在"真停住"时(1:4 @0.09)与真静止在速度、
   位移两类信号上不可区分(实测 d20 低到 0.0004 m),任何纯信号判据都会漏;
   这与共识 6"政策层显式命令、物理核不自主决策"自洽。
2. **被动体(P2 适用对象)的触发谓词加位移门**:P2′ = lin<0.1 ∧ ang<0.05 ∧
   **最近 20 tick 位移 ≤3 mm**,连续 20 tick。实测挡掉全部平地/滚动误触发、
   5/6 阶梯误触发,真静止/落定触发时延 0 tick(tick 20 照常)。2 mm 亦可
   (数据:合法 ≤1.4 mm,爬行 ≥6.3 mm,取中间偏松的 3 mm 留裕度)。
3. **不要把睡眠兜底当作误凝固保险**:对受驱实体它不生效(实测);对掉落物它
   同样会截断滑行(tick 31)。若需要收紧睡眠阈值,G 表明 Python 绑定改不动,
   得在 Rust 封装层配置。
4. 单位澄清建议回写 §4.3:阈值单位明确为 m/s / rad/s,并给出"0.1 m/s ≈ 每
   tick 1.67 mm ≈ 潜行速度 0.1 m/tick 的 1/60"这类换算,防止按 m/tick 误读。
