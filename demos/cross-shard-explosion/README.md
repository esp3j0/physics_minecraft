# Demo D:跨片效果的确定性计算(爆炸)

对应架构问题(REQ-001 分片交互层):分片之间不共享状态、互不感知;爆炸这类跨片事件收敛为
"各方用**共享输入** + **本地状态**独立计算,合并结果必须与单一世界一致"。本实验验证该等价性,
并给出爆炸冲量函数的输入清单(接口规格)。

## 怎么跑

```bash
.venv/Scripts/python.exe demos/cross-shard-explosion/main.py
```

爆炸冲量函数(纯函数、确定性,写进协议):

```
dist = |pos - center|
if dist >= radius: impulse = 0
else: impulse = (pos - center)/dist * power * (1 - dist/radius)   # 线性衰减
施加方式:apply_impulse(不除以质量 → 重球速度变化小)
```

**所需输入 = 共享 {center, power, radius} + 本地 {实体在爆炸 tick 的 pos}**,仅此四项。

场景:地面 y=0;分片边界 x=0;10 个球(左 4 / 右 4 / 贴边界 2,归属规则 `x<0 → 左片`)。
tick=60 施加爆炸(center=(0.3,0,0.5), power=6, radius=5),滚到 tick=300 比终点。
为隔离假设,球与球不碰撞(collision groups 只对地面)——球-球交互属于分片内部语义,
与跨片等价性无关(实体不会同时存在于两个分片,接触跨不了片)。

## 结论

1. **"共享输入 + 本地状态独立计算 ≡ 单世界一次计算"严格成立(位级一致)**,包括爆炸中心
   就骑在分片边界上的情形。前提是:每个分片拿到的共享输入**完全相同**、本地状态读取发生在
   **同一逻辑 tick**、冲量函数是纯函数。
2. 与任务书前期实测(同机两世界 200 步位置差 = 0)互相印证:分片各自计算不会引入跨片偏差,
   跨片事件不需要全局协调计算,只需要**广播共享输入**。

## 对 REQ-001 的具体建议

- 跨片事件协议:事件 = `{事件类型, tick(发生的逻辑 tick), 共享参数(如 center/power/radius)}`;
  由调度器在 tick N 广播,各分片在**自己的 tick N** 用本地实体状态独立求值(demo 证明无需
  任何跨分片物理查询)。这与 ferrumc v2 的 `CrossShardEnvelope`(apply_at = produced_at+1)
  同型——但物理事件的"应用 tick"应与发生 tick 一致,信封只保证送达,不改变生效节拍。
- 贴边界实体的归属规则必须唯一且确定(本 demo:`x<0 → 左`);归属规则写在分片坐标系定义里,
  而不是各事件临时决定。
- 后续真正的跨片难题只剩**实体迁移**(demo A 已给出无损方案)与**事件顺序**(同一 tick 多个
  事件的确定性排序,建议按 `(事件类型, 来源, 序号)` canonical 排序,借用 v2 信封排序键)。
