# demos/cohesion — REQ-010 任务 00:粘结/承载/复合体 demo

对应 [REQ-010](../../docs/requirements/REQ-010-cohesion-rigid-clusters.md)(D1–D9 已拍板,数值占位)
与任务书 `docs/tasks/req010-cohesion/00-demo.md`。4 个脚本回答占位数值问题并找出需求漏洞。
本文所有数字均来自实际运行输出(命令见下),无估算值。

## 运行方式

```bash
# 仓库根目录,解释器为已配好的 .venv(rapier3d==0.36.0 + numpy,不联网)
.venv/Scripts/python.exe demos/cohesion/load.py      # ~1.5 s,13 结构+B 扫描+切块+跨分片
.venv/Scripts/python.exe demos/cohesion/compound.py  # ~1.3 s,32 次落定+重叠+碰撞体对比
.venv/Scripts/python.exe demos/cohesion/fracture.py  # ~1.0 s,31 场景逐格冲量+断键判定
.venv/Scripts/python.exe demos/cohesion/bridge.py    # ~0.3 s,石桥三种塌落对比
```

坐标约定同 REQ-009 demo:格 (x,y,z) 覆盖 [x,x+1)³,地表 y=0;地形碰撞体按生产口径
用暴露面薄片(半厚 0.075),但**全部挂在一个固定体上、每片一个 primitive collider**
(不用 `Collider.compound`)——这是本次最重要的实测结论之一,见 §3.0。

## 1. load.py — 承载判定(纯体素,最大流)

按 REQ-010 §4 实现:接地格按柱缓存(numpy 向量化);悬挑区从触发格 BFS(只走非接地
实心格,超 `load_max_cells`=2048 截断按稳定);整数容量网络(源→悬挑格 1;正下 ∞;
水平/正上 `min(B_a,B_b)`;接地或未装载邻格连汇);最大流;F = 残量网络源可达集。

## 2. compound.py — 复合体落定(rapier)

4 形状(6 格梁 / L 形 4+3 / 2×2×2 / 3×1×3 板)× 8 落法(平落 1/2/5/10 m、竖落、
倾斜 20°/45°、垫 3 块),生成位姿严格落在合法网格位姿上(原点=格中心)。

- **整块凝固 26/32**。全部平落、竖落、20° 倾斜均通过(snap 位移 0.025–0.36 格、
  角度 ≤ 5.2°,远小于 0.5/45° 上限);
- 6 例失败全部是**真倾斜搁置**(D5 散开的正确输入):垫 3 块 4 例(位移 0.74–1.28,
  角 13–33°,其中 2×2×2 还出现目标格被垫块占用→走上移/散开路径)、45° 斜靠自锁 2 例
  (L 形与立方恰好停在 45° 整,位移 1.18/2.01);
- 6 格梁竖落会倾倒,733 拍才静止,但仍整块凝固 ✓;
- 质量 = 格数 × 0.729 实测全对(4.374/5.103/5.832/6.561)。

生成时初始重叠(断面旁 6 格梁,端面与生产薄片重叠 0.025,零速度):
前 10 拍最大速度 1.241 m/s(自由落体同刻 1.635),最大水平速度 **0.149 m/s**——
薄片重叠不会把复合体弹开;墙面摩擦让下落慢 ~25%(vy(10) −1.232 vs −1.635 m/s),
"沿断面滑出被卡住"存在但轻微,不粘死。

碰撞体做法对比(每格 cuboid vs 合并长方体):质量逐一相同,两者都整块凝固
(snap 误差同量级 0.025–0.09);静止拍数有差(62/75、128/74、63/66、70/70),
300 步单侧耗时都在 0.06–0.08 ms/步,**本规模无性能差**。

## 需求问题清单(纪律 8:现象 → 根因 → 建议)

1. **§4.3 无力矩最大流模型下,"4 柱撑 20×20 石平台"从满员状态就判塌(F=396,流 128)**。
   根因:板内每格重量只能沿同层水平粘结链走到接地位,每根柱顶格最多吸收 1+4B=33 格的
   流量,4 柱上限 ~132 ≪ 400;31×31"四边全长支撑"的板则恰好挂住(841 ≤ 边界容量 ~928,
   利用率 91%)——模型支持"梁/周边支撑板",不支持"点支撑板"。这是 §4.3 已知近似(无力矩)
   的极端表现,不是实现误差。建议:需求里写明"大板需要边/密支撑,点支撑大板必塌"
   (并进玩法教学);若想要"4 柱小平台"成立,只能提高 B 或接受;由总架构师裁定。
2. **跨分片"晚一拍"会把承载判定变成永久少塌(悬浮格)**。现象:土门楣 x=-3..3 跨 x=0,
   左柱∈A 被炸:A@t0 转 x=-3..-1;B@t1 看到剩余 3 格恰被单键容量 3 承住 → 判稳定 →
   (0,5,0)(1,5,0)(2,5,0) 永远悬空(单世界 F=6)。根因:REQ-009 连通性判定是单调的
   (少一边只会更容易塌),"晚一拍"只造成延迟;承载 F **非单调**(邻片塌掉后剩余结构
   "减负"可能变稳定),B 用缺了已塌格的视图求值得到偏小的 F,且之后不再有触发。
   建议:①邻片传来的 BlockWrite 区分"触发因"(爆炸/移除)与"承载因"(F 转换),
   承载因的写入下一拍才参与本片的判定输入(等价于各片都用"变化前"世界求 F,与单世界
   一致);②或接受为已知限制,写明"跨界承载结构的残余部分可能悬浮,由再次破坏触发"。
   推荐 ①。
3. **§7.1 复用 REQ-009 的 I 作撞击粘结,平落过碎**。现象:石梁平落 2 m 单格 J=27.5 ≥ 18
   断成 3 段;2×2×2 立方平落 1 m 也断;设计意图"石桥面从约 5 m 高平落不碎"。根因:
   §3.2 的高度估算假设平落冲量按底面格均摊(m·v/n);实测落点不对称(浮点与求解器顺序),
   首触格承受 5–30× 均摊值(27.5 vs 0.76),且竖落/角先的单格 J ≈ m·v+穿透修正本身
   就高于估算(1 m 竖落 21.3 > 18,"29 m 才碎"低估了 30 倍)。建议(按优先序):
   ①J 平滑——连续 ≥2 拍超阈或 3 拍滑动平均再断键,可把 2 m 平落的假尖峰滤掉而保留
   真撞击(32 m 峰值持续多拍);②I 另调(要平落 5 m 不碎需 I≳40,但角先/竖落"摔得碎"
   的门槛同时抬高,张力大,不推荐单靠调 I);③按接触几何归一(J_c × 底面接触格数/总格)。
   需要总架构师拍板;数据见 §3.1。
4. **"静置永不断键"成立,但桥式静置的端格载荷是均摊的 3 倍**。现象:两端搭块梁 300 拍,
   端格未过滤峰值 0.41(非端格 0)≈ 3×0.119。根因:悬空段重量全部经两端两格传入,
   静载集中。结论:静置断键不会发生(0.41 ≪ 7)✓;但若未来把 I 调低到 ~4 以下,
   "桥式静置"会最先误断,I 的下界校验应加"≥ 3× 端格静载"。
5. **接近速度 ≥ 1 m/s 的逐点过滤在 Python 绑定下只能用身体速度代理**。现象:本 demo
   以"步进前身体速度 ≥ 1 m/s"代替逐接触点接近速度。根因:逐点接近速度要
   body_pos+R·(collider 偏移+local_p1) 与法向点乘,绑定可算但多 2 次矩阵乘/点;
   且两场景的判定差异只出现在"整体慢速但局部快"的边缘。建议:生产(Rust)按 REQ-009 §5
   原义逐点过滤;demo 结论不受代理影响(静置 0.41、撞击 ≥11,分界清晰)。
6. **D8"放置触发"+B=8 满载悬臂 ⇒ "1 格沙压塌 8 格石悬臂"**。现象:悬臂末端放 1 格沙
   (B 沙=0 无粘结,纯压重),整根悬臂连沙同塌(F=9);REQ-009 NeedsBelow 口径沙不掉。
   根因:D8 拍板的直接推论,且 B=8 的 8 格悬臂恰好满载、任何加重都断。建议:接受并在
   玩法上把"满载悬臂"当刀刃案例;若不希望沙块压塌结构,可给"无粘结方块(沙)"的压重
   打折(如计 0.5 格重)——需总架构师裁定。
7. **§7.1 的"按 REQ-009 §5 方法采样"在 Python 原型里只能走"固定体+多 primitive"**。
   现象:REQ-009 记录复合 collider 接触冲量恒 0;本 demo 用"固定体上多个 primitive 薄片"
   完全可行(0.00%/3.1% 偏差)。根因:缺陷与 Collider.compound 相关;补充实测中单个
   compound collider 的静置冲量又读到了非 0(见 `_API_NOTES.md`),触发条件比原记录更窄。
   对生产无阻塞:REQ-009 撞击 spike 已证 Rust 侧复合 collider 可读。建议:实现单元 06 时
   先在 Rust 侧写一条"复合地形 × 复合实体"的冲量直读单测,失败再降级动量差分。
8. **弹坑地面的承载判定代价实测接近零,但代价在"接地缓存"**。现象:60 触发格 → 悬挑区
   0 格、跳过最大流,整个求值 1.45 ms 全部花在逐柱接地高度重建(61×61 柱的 numpy 扫描)。
   根因:demo 每次求值重建缓存;生产按 §4.2 做成随体素写增量维护的柱缓存后,触发判定
   本体只是"触发格 6 邻检查"。建议:实现时接地高度随写入增量维护,并在遥测里单列
   "缓存命中/重建"计数。
