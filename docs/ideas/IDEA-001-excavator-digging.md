# IDEA-001:挖掘机与地形破坏

- 状态:**设想**(部分并入 [REQ-007](../requirements/REQ-007-activation-tickets.md),见各条标注)
- 提出日期:2026-10-20
- 来源:用户设想 + 当日讨论梳理

---

## 1. 场景

未来加一个挖掘机实体(底盘 + 大臂 + 斗杆 + 铲斗,多刚体关节),用铲斗挖地形、装土、卸土。

## 2. 用户原始设想

1. 方块持续受力达到阈值、但没有移动 → 掉落(可以理解为"内能"累积到一定程度),类似 Minecraft 的挖掘掉落;
2. 方块受力并且移动了 → 一直移动;
3. 实体接触地面时激活票据?用有限元预测激活哪些?

## 3. 梳理

### 3.1 前提:体素本身不会"移动"

地形在 rapier 里是每 chunk 一个合并过的固定复合体,不会动。"受力移动"只可能发生在方块**变成实体之后**,
所以设想 1 和 2 需要改写成**破坏那一刻的二选一**:推得动就脱离成实体去运动,推不动但持续超载就磨碎。

### 3.2 统一判定:力 vs 强度

每个方块每拍由接触点算出受力 F:

```
F > S_结合                 → 脱离:变成瞬态实体,带着推力运动                (设想 2)
Y < F ≤ S                  → 损伤累积 D += (F − Y)·dt;D ≥ 硬度 H → 磨碎      (设想 1)
F ≤ Y(屈服阈值)            → 什么都不发生;不受力时 D 逐渐衰减
```

- 结合强度 S ≈ 材料黏聚力 × 与邻居相连的实心面数:地表一块土只连着下面一个面,很容易推走;墙体里的一块
  连着五个面,只能磨;
- 材料参数示例:沙黏聚力 0(推就动、悬空就落),土中等,石很高(基本只能磨),基岩无穷大;
- **屈服阈值 Y 必须有**,否则静载会累积损伤,重型实体停在地上会自己慢慢陷下去;
- 可选:只有带"工具"标记的碰撞体(斗齿、钻头)才造成损伤,避免碎片乱弹把地形磨坏。

### 3.3 设想 3:接触 ≠ 激活

- 地面被一切东西接触着(每个落地的方块、每个站着的怪),接触不能作为激活条件;
- 挖掘机自己的票据(观察者票或常驻运动票,见 REQ-007)已经保证铲斗周围 ①② 加载,不需要另发票;
- 地形没有"醒着"状态。把完好的地形预先转成刚体,会毁掉廉价的复合碰撞体,rapier 也撑不住上千个堆叠立方体。
  地形只应该**在失效时**变成实体;
- **有限元的正确用途是结构分析**:(a) 载荷会不会把没直接碰到的块也压坏(应力扩散);(b) 挖空后剩下的结构
  稳不稳(坍塌);
- 起步建议:(a) 只让直接接触的块累积损伤(像 Minecraft,玩家好预测);(b) 局部连通性洪泛找悬空块群;
  有限元等 demo 比较代价与效果再定。候选方案:
  - 连通性洪泛找悬空岛(Teardown 式,最便宜);
  - 沿支撑图传播载荷(7 Days to Die 式);
  - 局部体素有限元(线弹性、六面体单元,只算冲击邻域;同机确定,每次可能数毫秒到数十毫秒)。

### 3.4 新增的形态转化

| # | 从 → 到 | 触发 | 谁决定 | 票据 |
| --- | --- | --- | --- | --- |
| T8 | 体素 → 实体(脱离) | 推力 > 结合强度 | **owner 分片** | 新实体签发瞬态运动票 |
| T9 | 体素 → 移除或掉落物(磨碎) | 损伤 ≥ 硬度 | **owner 分片** | 掉落物若是实体则签票 |
| T10 | 体素 → 实体(坍塌) | 失去支撑 | owner + 结构分析 | 签票 |

现有通道只有"实体 → 体素"(凝固、强制落地),体素永远变不成实体(REQ-001 共识 6)。挖掘就是打开反向通道。

### 3.5 跨分片

- 实体 ↔ 地形跨边界可以(margin 副本);实体 ↔ 实体跨边界不行(REQ-001 §9.13)。边界上挖出来的块迁到
  邻片后,铲斗会从它身上穿过去;
- 多刚体挖掘机跨边界不行,**前置依赖关节组迁移**(#13 §7);
- **同格写入冲突**:按代码推断,凝固格总在实体中心所在格,也就是生产者自己的核心区,所以至今没有出现过
  跨片写同一格。挖掘第一次打破这个前提(A 片的铲斗破坏 B 片核心区里的格,A 只有副本)。需要 **owner 仲裁**:
  holder 把接触冲量转发给 owner(晚一拍),owner 累积、决定、广播;脱离出的实体在 owner 分片生成。

### 3.6 漏洞清单

1. 静载侵蚀 → 屈服阈值 Y;
2. 体素不会移动 → 破坏时二选一(§3.2);
3. 磨碎后原地变实体会立即再凝固(死循环);铲斗里的土会凝固在半空 →
   - 释放后保护期内不凝固(待定);
   - **凝固前提"无实体支撑"、被承载时截止拍暂停 —— 已并入 REQ-007(§4.7、§4.3)**;
4. 地形碰撞体是贪心合并的大盒子,子形状序号对不上方块 → 用接触点减法向小量反推格坐标;
5. 接触 ≠ 激活(§3.3);
6. 跨片同格写入冲突 → owner 仲裁(§3.5);
7. 大量释放 → 醒体预算到顶走强制落地;同 chunk 碰撞体每拍只重建一次;
8. 损伤值是否持久化:进 checkpoint 保确定性,chunk 卸载时丢弃(Minecraft 也是停手重置)—— 待定;
9. 大块崖壁塌落应整体作为一个"体素块实体"(多格复合刚体),而不是 N 个立方体 —— 新实体形态,待定;
10. **挖掉冻结体脚下的方块,冻结体悬空 → 地形变更唤醒,已并入 REQ-007(§4.11)**;
11. **冻结的一叠实体只唤醒下面的,上面的悬空 → 支撑闭包,已并入 REQ-007(§4.9)**。

### 3.7 一铲子的完整流程

1. 玩家驾驶挖掘机(常驻体),观察者票覆盖,醒着;
2. 斗齿压进土里,owner 分片按接触点算每格受力;
3. 地表土块 F > S 脱离成瞬态实体,被推进铲斗;墙里的土块累积损伤,磨碎后成松散实体;
4. 抬铲斗:斗里的土被实体承载,不凝固,截止拍暂停;
5. 卸土:落到地面静止后凝固(有地形支撑),堆成土堆;
6. 坑壁悬空部分由结构分析判定坍塌;
7. 玩家离开:挖掘机静止则冻结,斗里的土随之冻结(承载静止);仍在动则持常驻运动票直到静止。

### 3.8 票据扩展

- 挖掘机在无人观察处自动作业 → 新票种"作业票":持有者 = 挖掘机实体,区域 = 作业半径。
  REQ-007 的票据键是"持有者 × 种类",一个实体可同时持运动票和作业票,模型已预留。
