## 1. 项目定义

把激活从"观察者坐标驱动的隐式规则"升级为**显式、可扩展的票据体系**,并据此修掉
"蓝方块悬空冻结"一类问题:

- **三档真正拆开**:① 地形数据 / ② 碰撞体 / ③ 清醒,各有独立半径与预算;
- **统一票据模型**:票据 =(持有者 × 种类)→ 区域规格 / 唤醒规格 / 时钟 / 状态。本 REQ 实现四种:
  **观察者票**、**区域票**、**瞬态运动票**、**常驻运动票**。激活、ensure、分片保活只读票据的通用规格,
  新票种只需追加;
- **票据转递**:迁移、传送、类别切换、承载、冻结/唤醒时票据如何签发、暂停、挂起、恢复、终结,
  有统一的操作与规则表,并为分裂/合并/骑乘等未来场景预留;
- **冻结只发生在静止时**:运动中的实体持运动票保持清醒;静止后,有地形支撑的瞬态体凝固,
  被实体承载的瞬态体与常驻体才会冻结(超预算等兜底除外);
- **唤醒统一**:观察者、区域票、接触、地形变更、命令五种来源走同一套规则:当前足迹地形就绪、
  向上支撑闭包整组原子唤醒、静止窗口重置;
- "醒着 ⇒ 脚下有碰撞体"变成**显式不变量**,缺地形时进入"待地形"而不是穿地。

一句话:**谁需要地形/清醒,就持票声明;运动中的东西不会被冻结,瞬态体保证落地凝固。**
这是 #13 后续(弹道代理、信号网络、事件票)与破坏/挖掘玩法(IDEA-001)的共同地基。

## 3. 现状(代码证据)

### 3.1 每拍激活链路

```
tick N
 ├─ 观察者收件箱 → observer_table                         (scheduler.rs tick() 1.2)
 ├─ 每分片 apply_activation(全局观察者坐标)                (scheduler.rs tick() 1.5)
 │    ├─ plan():chunk 装/卸决策(外露,不在此执行)
 │    └─ 实体冻结/唤醒立即落实(刚体类型切换)
 ├─ 分片并行 apply_prefix → step(物理 → 凝固 → 迁移检测)
 └─ outbox 汇总、despawn 候选(空片 + 无票 + idle)
tick N 结束 → 驱动 orchestrate()                           (driver.rs)
 ├─ ensure:观察者 32m 内分片 + 在途信封目的分片
 ├─ chunk 装/卸执行(load_chunk 同时写体素 + 建 collider)→ N+1 生效
 └─ despawn 落库(flush 屏障)
```

### 3.2 一个观察者的激活范围(默认配置)

| 维度 | 半径(进/出) | 口径 | 数量(观察者在 chunk 中心) | 定义处 |
| --- | --- | --- | --- | --- |
| chunk(数据 + collider **合一**) | 32 / 48 m | 水平,到 chunk 中心 | 进 13 个,滞回最多 29 个 | `activation.rs::plan` |
| 实体清醒 | 24 / 32 m | 3D | 不计个数,每片上限 512 | `activation.rs::plan` |
| 分片 ensure | 32 m(= `awake_unload_radius`) | 到分片核心 | 1–4 片 | `driver.rs::orchestrate` |
| 分片保活票 | 48 m(= `chunk_unload_radius`) | 到分片 AABB | — | `scheduler.rs::shard_is_ticketed` |

预算:每片每拍装+卸合计 2 chunk;chunk 与实体冷却 180 拍(装载也受冷却)。

### 3.3 缺口

1. **瞬态体悬空冻结(蓝方块)**:新实体(spawn/迁移重建/传送重建)无翻转记录、不受冷却保护,
   离最近观察者 > 32 m 的下一拍即被冻结(kinematic、清速)。被炸飞的碎片冻在半空,不凝固、不受爆炸。
   常驻体同理:运动中离开观察者范围也会被冻在半空。
2. **冻结体钉死分片**:despawn 要求 `entity_count == 0`,`unload_shard` 对非空分片 panic。
3. **"醒着 ⇒ 有地形"只是隐式保证**:靠 24 m < 32 m 的半径差。破绽(代码推断,未复现):chunk 装载受
   180 拍冷却;实体先冻结、chunk 后卸载,实体冷却先到期 → 观察者 3 s 内快速折返时实体可能被唤醒而
   脚下 chunk 仍在冷却未装 → 穿地坠落。
4. **三档名不副实**:REQ-001 列 ① 数据 / ② collider 两档,代码 `load_chunk` 合一。
5. **冻结体是空中的墙**:kinematic 零速体对醒着物体表现为不可推动的障碍,撞击动量被原样反弹。
6. **观察者的四种职责(装载中心、唤醒中心、分片 ensure、分片保活)分散在三处,半径各自取值。**
7. **压在实体上的方块会凝固在半空**:凝固桥只看速度/睡眠,不看支撑来源。方块落在常驻体上静止即凝固,
   常驻体走开后留下悬空方块。
8. **冻结体不响应地形变化**:脚下方块被 `SetBlock` 等移除后,冻结体悬在空中。

## 4. 设计

### 4.0 激活启用开关(D17)

**现状**:调度器 `observers_ever_set == false` 时激活完全跳过,`ShardSim.observed == None` 时激活不生效,
行为与没有激活机制时一致。大量既有用例在这个模式下手动装载 chunk 运行,例如
`physics-sim/tests/shard_sim.rs`、`shard/tests/two_shards.rs`、`e2e/tests/migration.rs`、
`sim-api/tests/replay.rs`、`app/tests/app_e2e.rs`。

**规则**:

- 把开关推广为"**激活已启用**":调度器曾经设置过观察者**或**区域票即为启用。单向,不回退;随快照保存
  (沿用现 `observers_ever_set` 的快照位置与语义)。
- **未启用时,行为与 `8702670` 完全一致**:
  - `load_chunk` / `apply_chunk_load` 同时建 ① 和 ②;
  - 不派生任何票据,不校验 I2、I3;
  - 没有待地形、强制落地、虚空移除、凝固前提修订、接触唤醒、地形变更唤醒,冻结规则不变。
- **启用当拍**(bootstrap):
  - 为全部存活或在途的瞬态体签发 `TransientMotion`,时钟从该拍起算;
  - 当时已建碰撞体的 chunk 即为初始 ② 集合;
  - 此后本 REQ 的全部规则生效,`apply_chunk_load` 只装 ①,② 由激活决策构建。

**理由**:不加这个开关,上述既有用例会因为"装载只建 ①""实体缺地形进入待地形""无地面下坠被虚空移除"
等新规则大面积失败,迫使 §9 白名单之外的大量测试改动。生产环境(app 驱动)总会设置观察者,不受影响。

### 4.1 三档拆分(D5)

| 档 | 内容 | 来源 / 执行方 | 成本 |
| --- | --- | --- | --- |
| ① 地形数据(Data) | chunk 体素进 `VoxelWorld` | provider(IO),驱动 orchestrate 执行 | IO + 内存 |
| ② 碰撞体(Collider) | chunk compound 静态体 | 由内存中的 ① **纯函数派生**,`ShardSim` 在 `apply_activation` 内自行构建/拆除(无 IO) | 0.3–1.4 ms/chunk |
| ③ 清醒(Awake) | 实体为 `Dynamic` 参与解算 | `ShardSim`(§4.9) | 解算 |

不变量(fail-stop 断言):

- **I1 ② ⊆ ①**:任一 chunk 有 ② 必有 ①。卸载 ① 时同步拆除其 ②(同一执行点,不额外占预算)。
- **I2 醒着 ⇒ 当前足迹地形就绪**:醒着的实体(`Dynamic`),其**当前足迹**(§4.5.2)与本分片区域
  (`core ∪ margin_ring`)交集内的每个 chunk 都有 ②。不满足时按 §4.6 进入"待地形"或推迟唤醒。

细则:

- REQ-005 的 owner/holder、区域过滤、BlockWrite 投递针对 **①**;② 是分片本地派生缓存,不参与
  owner/holder 语义。
- ② 构建时用已装载邻居的 ① 做面剔除(沿用 `neighbors_of`);邻居 ① 装/卸时,**已有 ② 的**邻 chunk
  重建(沿用 `expand_boundary` 语义),此类重建不计预算(同 SetBlock 重建)。
- 有 ① 无 ② 的 chunk 收到 SetBlock / BlockWrite:写体素,不建本 chunk 的 ②,已有 ② 的邻居照常重建。
- 预算拆开:① 每拍装+卸合计 `data_budget_per_tick`;② 每拍构建 `collider_budget_per_tick`
  (拆除不计)。冷却同样分档簿记。
- 执行时序(修订 5,D18):① 装载决策在 N 拍产生、拍末由驱动执行 → N+1 可用。② 分三种情况:
  1. **随 ① 同点构建**:同一份决策里,某 chunk 的 ① 装载被采纳,且此刻它也满足 ② 构建条件
     (距离 ≤ `collider_load_radius`、② 冷却已过、② 预算有余),则它的 ② 也在 N 拍决定,并在
     ① 装载完成的同一执行点立即构建;
  2. **单独构建**:① 已在内存、② 缺失且满足构建条件的 chunk,在 `apply_activation` 中(`step` 之前)构建;
  3. **拆除**:同一份决策中 ① 被卸载的 chunk,② 随 ① 在卸载点一起拆(I1);**单独拆 ②** 只在 chunk 的 ①
     仍被保留时发生,即距离 ≤ `data_unload_radius`(或仍在某张票的 ① "出"区域内),而 ② 已超出
     `collider_unload_radius`。① 已该卸、只是因预算或冷却排队等待的 chunk,② 保持不动。

  默认配置(①② 半径、预算相同)下,② 集合与 ① 集合**逐拍相等**,碰撞体的出现和消失时刻与现状逐 step 一致。
  决策仍只在 `plan`(§14 第 1 条不变),执行点由 `ShardSim` 负责,驱动层不执行 ②。
- **"② 已建"是独立状态**(D18):用"已建集合"登记,与 chunk 是否生成了碰撞盒无关。全空气 chunk 的
  碰撞体为空,但同样算作 ② 已建,否则会被反复重建,并在 I2 判定中被误认为"缺地形"。

### 4.2 票据模型(D10 扩展性)

#### 4.2.1 结构(形状示意,定语义不定实现)

```text
TicketKey    = (holder: TicketHolder, kind: TicketKind)     // 全局唯一键,票据表按键有序
TicketHolder = Observer(InputSource) | Entity(EntityId) | Area(AreaId)      // 只追加
TicketKind   = Observer | Area | TransientMotion | ActorMotion             // 只追加

Ticket {
    key:      TicketKey,
    priority: u8,                 // 预算排序,小者优先
    data:     RegionSpec,         // ① 覆盖
    collider: RegionSpec,         // ② 覆盖,必须 ⊆ data
    wake:     WakeSpec,           // ③
    clock:    TicketClock { issued_at: Tick, active_ticks: u64,
                            limit: Option<u64>, starts_at: Option<Tick> },
    state:    Active | Paused | Suspended,
}

RegionSpec = None
           | Radius { load_m, unload_m }        // 以锚点为圆心、水平半径、带滞回
           | Footprint { lookahead_ticks, max_lookahead_chunks }   // 随实体,见 §4.5.2
           | Chunks(BTreeSet<ChunkPos>)          // 固定 chunk 集
WakeSpec   = None
           | SelfOnly                            // 只保证持有者自身清醒
           | Radius { load_m, unload_m }         // 唤醒范围内的他人(3D)
```

- **锚点每拍由持有者派生**:观察者坐标 / 实体当前状态(在途时取迁移载荷状态)/ 区域票自身的中心。
- **状态**:
  - `Active`:占用区域,时钟走;
  - `Paused`:占用区域,时钟停(用于"被承载");
  - `Suspended`:不占用区域,时钟停(用于"承载静止冻结")。
- `starts_at` 本 REQ 恒为 `None`,为落点预约票预留;`limit` 是以 `active_ticks` 计的上限。
- 一个持有者可以同时持多种票(键含 kind),例如将来挖掘机同时持运动票和作业票。

#### 4.2.2 扩展性硬性要求

1. **激活决策(`plan`)、分片 ensure、分片保活只消费 `RegionSpec` / `WakeSpec` / `priority` / `state`,
   不得对 `TicketKind` 分支**。种类相关的逻辑只允许出现在签发与转递(§4.3)。评审检查项见 §14;
2. `TicketHolder`、`TicketKind`、`RegionSpec`、`WakeSpec` 均为**只追加**枚举,序列化随 `format_version` 管理;
3. 票据表是调度器级全局唯一一张,按 `TicketKey` 有序;任何遍历都按键序。

#### 4.2.3 本 REQ 的四种票

| 票据 | 持有者 | ① / ② | ③ | 时钟 | 优先级 | 产生方式 |
| --- | --- | --- | --- | --- | --- | --- |
| **观察者票** | `Observer(source)` | `Radius` 32/48 m | `Radius` 24/32 m | 无上限 | 0 | `SetObserverPosition` / `RemoveObserver`(入日志) |
| **区域票** | `Area(id)` | `Radius`(中心 + 半径) | 可选 `Radius`(同半径)或 `None` | 可选 TTL | 1 | 新命令 `SetAreaTicket` / `RemoveAreaTicket`(入日志,仅本地命令通道) |
| **瞬态运动票** | `Entity(id)` | `Footprint` | `SelfOnly` | `limit = transient_settle_deadline_ticks` | 1 | 派生(§4.3) |
| **常驻运动票** | `Entity(id)` | `Footprint` | `SelfOnly` | `limit = actor_motion_max_ticks` | 1 | 派生(§4.3) |

**区域票**(D10):

- 用途:无观察者也能让一片区域保持加载和唤醒,用于测试、服务器保活区域,并验证模型对
  "非观察者、非实体"持有者与 TTL 的通用性。将来的事件票、信号执行端票、作业票与它同构;
- 命令形状:`SetAreaTicket { id: AreaId, center: Vec3, radius_m, tiers: ①|①②|①②③, ttl_ticks: Option }`
  (同 id 覆盖)、`RemoveAreaTicket { id }`(不存在 = 幂等);
- 与观察者命令一样走**调度器级票据收件箱**(由现 `observer_inbox` 推广而来),永不进入分片输入前缀;
- 只开放给本地受信命令通道(驱动 commands 通道 / `Session`),**不进 C2S 白名单**;
- 约束:`radius_m ≤ area_ticket_max_radius_m`,同时存在的区域票 ≤ `area_ticket_max_count`;
  超限返回类型化拒绝,不 panic。

#### 4.2.4 未来票种如何落位(不在本 REQ 实现,模型必须能表达)

| 未来票据 | 持有者 | ① / ② | ③ | 时钟 | 来源 |
| --- | --- | --- | --- | --- | --- |
| 事件票(远处爆炸、信号热执行) | `Area`(自动分配 id) | `Chunks`(爆心/执行端邻域) | `Radius` | 短 `limit` | 模拟派生 |
| 落点预约票(弹道代理) | `Entity` | `Chunks`(落点邻域) | `SelfOnly` | `starts_at` + `limit` | 模拟派生 |
| 作业票(挖掘机自动作业,IDEA-001) | `Entity` | `Radius`(作业半径) | `SelfOnly` 或 `Radius` | 任务期 | 玩法层 |
| 管道票(高速飞行) | `Observer` / `Entity` | 追加 `RegionSpec::Tube` | `None` | — | 模拟派生 |

### 4.3 票据转递(D10)

#### 4.3.1 操作

| 操作 | 语义 |
| --- | --- |
| `Issue` | 新建票。观察者/区域票:键已存在 → 覆盖更新(规格、TTL 按新命令)。**实体票:键已存在 → 无操作,不重置时钟、不改状态(幂等)** |
| `End` | 删除票。**全部幂等**:票不存在 → 无操作 |
| `Pause` / `Unpause` | `Active ↔ Paused`;已在目标状态 → 无操作;票不存在 → 无操作 |
| `Suspend` / `Resume` | `→ Suspended` / `Suspended → Active 或 Paused`;同上幂等 |
| `Transfer`(预留) | 把时钟从一个键转给另一个键(将来用于分裂/合并);本 REQ 不实现,但票据表接口要留出位置 |

**为什么全部幂等**(D14):同一拍内,同一张票可能被不同路径重复操作。例如常驻体静止时分片发出
`End ActorMotion`,同拍它又因 `MarkActor`/移除而终结,调度器的终结判定也会 `End`;又如 `apply_activation`
与 `step` 中的接触唤醒可能对同一实体各发一次 `Issue`。把"操作不存在的票"当错误会产生误报。
正确性改由 §4.3.6 的不变量 **I3** 在每拍末校验,违反即 fail-stop,比逐条操作报错更严格。

#### 4.3.2 数据流

- **实体票**:操作由分片在 `apply_activation` / `step` 中判定,写入 `Outbox` 新字段(例如 `ticket_ops`);
  调度器在 N 拍末按 `TicketKey` 序应用,**N+1 拍生效**;
- **观察者票 / 区域票**:票据收件箱在 N 拍开头应用(同现 1.2 步),当拍生效;
- **时钟推进**:调度器在每拍末对 `Active` 票 `active_ticks += 1`;
- **到期**:调度器在 N 拍末发现 `active_ticks ≥ limit` → 区域票直接 `End`;实体票向其 owner 分片
  投递**内部指令**(`InputSource::SCHEDULER` 来源,`apply_at = N+1`,不进外部命令日志,回放确定性再生),
  分片执行到期动作(瞬态:强制落地;常驻:撤票)。

#### 4.3.3 终结与迁移的区分

调度器判定实体终结的唯一规则:实体出现在本拍 `despawned` 中,**且**不在本拍迁移意图中,**且**没有在同拍
重新 `spawned`(传送)。满足 → 对其全部实体票 `End`。迁移在途期间票据保持,锚点取在途载荷状态。

#### 4.3.6 不变量 I3:票据与实体一致(D14)

调度器在每拍末(应用完 `ticket_ops` 与终结判定之后)校验,违反即 fail-stop:

1. 每个**存活或迁移在途**的瞬态体,恰好持有一张 `TransientMotion` 票;
2. 每张实体票的持有者都是存活或迁移在途的实体(不存在指向已终结实体的票);
3. 瞬态体不持 `ActorMotion`,常驻体不持 `TransientMotion`;
4. 冻结的常驻体不持 `ActorMotion`;承载静止冻结的瞬态体,其 `TransientMotion` 处于 `Suspended`。

"存活"以 `EntityOwnership` 为准,"在途"以 Router 中待投递的迁移信封为准。

### 4.4 实体分类、支撑与状态机(D1、D11)

#### 4.4.1 定义

- **瞬态体**:`actor == false`(碎片、方块、投射物),归宿是凝固;
- **常驻体**:`actor == true`(未来的怪物、机械狗、载具);
- **静止**:低速(`linear/angular_threshold`)连续 `consecutive_ticks` 拍且位移门通过,或 rapier 睡眠。
  与 `solidify.enabled` 无关。**任何唤醒都重置静止判据**(`slow_ticks = 0`、位移窗口只留当前位置),
  避免带着冻结前的旧窗口被误判静止;
- **支撑**:对醒着的实体 E,在 `step` 后检查其接触对。若接触法向(从对方指向 E)满足
  `n · û ≥ support_normal_min`(`û` = 重力反方向单位向量),对方即为 E 的支撑。
  对方是 chunk 静态体 → **地形支撑**;对方是实体 → **实体支撑**。零重力时不判定支撑;
- **被承载**:有至少一个实体支撑。

#### 4.4.2 冻结与凝固规则

| 实体 | 运动中 | 静止,且未被承载 | 静止,且被承载 |
| --- | --- | --- | --- |
| 瞬态 | 醒着,持瞬态票 | **凝固**(现有凝固桥) | **按常驻规则**:不在任何唤醒范围 → 冻结(票 `Suspend`);范围内醒着 |
| 常驻 | 醒着;不在任何唤醒范围时持常驻票 | 不在任何唤醒范围 → 冻结 | 同左 |

冻结条件汇总:**静止 ∧ 不在任何票据的唤醒范围内 ∧ 翻转冷却已过 ∧(常驻体 ∨ 被承载的瞬态体)**。
例外兜底:超预算淘汰的常驻体(§4.12)、常驻运动票到达上限,可能在运动中冻结(计入遥测)。

### 4.5 运动票

#### 4.5.1 签发与终结

见 §4.3.4。补充:

- 常驻运动票的签发**不要求**翻转冷却已过。只要醒着、运动中、不在任何唤醒范围,就签发,以尽早保证地形;
- 瞬态运动票的上限以 `active_ticks` 计,`Paused` / `Suspended` 期间不计。

#### 4.5.2 两种足迹(D13)

- **当前足迹**:实体 AABB(取 `half_size·√3` 作为旋转包络)外扩 `terrain_guard_m` 覆盖的 chunk
  (水平投影,chunk 为全高柱)。用于 I2、待地形判定、唤醒前置条件、强制落地。
- **预载足迹** = 当前足迹 ∪ 前视:当前足迹沿水平速度扫掠 `motion_lookahead_ticks` 拍覆盖的 chunk,
  最多 `motion_max_lookahead_chunks` 个(按到实体距离升序截断)。**只用于票据的装载请求**,
  不参与 I2,前视 chunk 没装好**不会**让实体进入待地形。
- 预载足迹中超出本分片区域的 chunk,由其 owner 分片按票据装载(ensure 保证 owner 存在)。
  实体在到达前已按 MARGIN 规则迁移过去。

超出前视上限的高速物体,可能在当前足迹缺 ② 时进入待地形(安全降级,表现为顿挫)。
正式的高速方案留给后续 REQ(D4)。

#### 4.5.3 为什么瞬态票的生命周期与实体合一(D2)

- 静止在凝固桥里**本来就是终结的前奏**:睡眠兜底当拍凝固,低速路径最多 20 拍,实体消失,票据随之消失;
- 如果静止就回收票据、实体却还没凝固(snap 误差过大在等待),它就失去地形保证:要么冻结
  (回到蓝方块和钉死分片的老问题),要么被撞醒时脚下 chunk 已卸载而穿地;
- rapier 的睡眠不是终态,接触或冲量会把它唤醒;票据必须覆盖到实体真正离开模拟为止;
- 截止拍不是第二套回收机制,而是同一生命周期的**上界**,兜住停不下来的情况
  (斜坡滚动、两物抖动、卡在缝里、下坠)。被承载期间暂停计时,避免载具上的货物被强制落地。

常驻体不会凝固,静止后冻结安全且不可见(它已停稳),所以常驻票持有到静止为止。

### 4.6 待地形(I2 的执行)

- **判定点**:每拍 `apply_activation`(`step` 之前),以及实体出现时(`spawn_entity` 内)。
- **进入**:醒着的实体当前足迹 ∩ 本分片区域内任一 chunk 缺 ② → 保存 `linvel/angvel`,切 Kinematic。
- **恢复**:上述 chunk 的 ② 全部就绪 → 切回 Dynamic,**原样写回保存的速度**(位置未变)。
- **期间**:不计醒数、不参与凝固/迁移检测、事件免疫、不参与接触唤醒(既不当撞击者也不被唤醒)。
  票据时钟照常计时。
- **装载优先**:缺失的 ①/② 请求属于**阻塞请求**(§4.12),不受冷却门控,排在所有票据请求之前。

### 4.7 凝固前提修订(D11)

现有凝固桥(P2′ 低速 + 位移门 / 睡眠兜底)追加前提:**该实体本拍没有实体支撑**。被承载的瞬态体不凝固,
按 §4.4.2 处理。

- 零重力场景不判定支撑,既有零重力凝固用例行为不变;
- 叠放在另一个尚未凝固的瞬态体上的方块,要等下层先凝固(下层变成地形)后才凝固,顺序自然成立。

### 4.8 强制落地(降级凝固)

纯体素算法,只读实体所在柱的 ①,不经 rapier:

1. 取实体中心所在格 `c`(与凝固桥同口径);
2. 若 `c` 为实心:向上找第一个非实心格(不超过 `WORLD_Y_MAX`)作为候选;
3. 否则向下扫描,直到下一格为实心,该格为候选;扫到 `WORLD_Y_MIN` 仍无支撑 → **虚空移除**;
4. **候选格与本分片任一其他实体的 AABB 重叠** → 沿柱向上找第一个既非实心、也不与任何实体重叠的格;
5. 落点写入 `desc.block`,删实体。产出与凝固桥一致:`Outbox.block_updates` 的 `Emergent` + `despawned`,
   复用 REQ-005 的 BlockWrite 广播与持久化路径。

触发:瞬态票到期(§4.3.2 内部指令)、超预算淘汰(§4.12)。
前置条件:实体中心柱的 ① 在内存;不在则推迟,该 ① 以最高优先级、不受冷却地请求。

**虚空移除**对所有实体生效:中心 `y < WORLD_Y_MIN − void_despawn_depth_m` 即删除(常驻体也一样)。

### 4.9 唤醒(统一规则,D12)

**来源**:

| 来源 | 触发 | 冷却门控 | 预算 |
| --- | --- | --- | --- |
| 观察者票 / 区域票 | 冻结体进入 `WakeSpec::Radius` 唤醒半径 | ✅(现状) | 先唤醒,再按距离淘汰(现状) |
| 命令 | Spawn / Teleport 重建即醒(现状) | — | 现状同拍淘汰 |
| 接触(§4.10) | 撞前预测 / 补偿 | ❌ | **只占空闲预算**,不淘汰他人 |
| 地形变更(§4.11) | 支撑格被改写 | ❌ | **不受预算截断**(当拍允许超限,后续按常规淘汰) |
| 支撑闭包 | 随上述任一来源 | ❌ | 与触发它的来源同组 |

**共同规则**:

1. **前置**:被唤醒者的当前足迹 ∩ 本分片区域 ② 齐;否则推迟(保持冻结),并以不受冷却的方式请求装载;
2. **支撑闭包(向上)**:被唤醒实体之上、与它贴靠(间距 ≤ `contact_wake_skin_m`)且中心更高的冻结实体,
   递归加入同一组。按几何判定(rapier 不为 kinematic–kinematic 对生成接触)。
   **一组原子生效**:整组都满足前置条件且预算允许才唤醒,否则整组推迟。这样不会出现"下面的醒了走开、
   上面的悬空"。
   **预算口径(修订 6,D19;修订 7 补例外)**:成员数 ≥ 2 的组,要求"当前醒数 + 组大小 ≤
   `max_awake_dynamic`",放不下就整组推迟,不走"先唤醒再淘汰",以免淘汰把组拆开。单个实体的观察者/区域票/
   命令唤醒保持现状(先唤醒,再按距离淘汰),AC-T1 不受影响。**例外:地形变更唤醒**(§4.11)不受预算截断,
   单体和整组都当拍允许超限——支撑已被移除,推迟就意味着悬空;
3. **重置静止判据**(§4.4.1);
4. 记入翻转簿记;按 §4.3.4 签发/恢复票据。

### 4.10 接触唤醒与唤醒范围(D3、D7)

#### 4.10.1 为什么必须"撞前预测"

冻结体对求解器等于无限质量。如果等接触发生后才唤醒,这一步里 rapier 已经把撞击者当撞墙反弹了;
下一拍醒来的冻结体从零速度开始,拿不到任何动量。所以**主路径是撞前预测**:在物理步进前找出这一步内
将被撞到的冻结体,当拍唤醒,让 rapier 在同一步里按两个动态体解算碰撞与动量交换。

#### 4.10.2 种子(谁被直接撞到)

- **时机**:`ShardSim::step` 开头(`apply_prefix` 之后、物理步进之前),此时命令与爆炸冲量已施加;
- **候选**:对每个醒着的实体 A(`EntityId` 升序),取其扫掠体:旋转包络 AABB 沿 `v_A` 扫掠
  `contact_wake_lookahead_ticks` 拍,再外扩 `contact_wake_skin_m`。与之相交的**冻结实体** B
  (常驻体或被承载的瞬态体)为候选;
- **冲击动量**:`p_AB = m_A · max(0, v_A · n̂_AB)`,`n̂_AB` 为 A 中心指向 B 中心的单位向量;
  同一个 B 被多个 A 命中取最大值;
- **门槛**:`p_AB ≥ contact_wake_min_momentum` → B 为种子,`p(B) = p_AB`。静止接触 v≈0、p≈0,天然不触发。

#### 4.10.3 传播(唤醒范围由动量决定)

- **冻结邻接图**:两个冻结实体碰撞形状间距 ≤ `contact_wake_skin_m` 即相邻(几何查询,纯函数);
- **最大动量传播**:从全部种子出发,`p(子) = contact_wake_decay · p(父)`,每节点取所有路径中的最大值
  (优先队列,同值按 `EntityId` 升序);`p < contact_wake_min_momentum` 或跳数 > `contact_wake_max_hops` 停止;
- **成组与截断**:每个结果节点按 §4.9 做支撑闭包成组;组按组内最大 `p` 降序、最小 `EntityId` 升序排序,
  依次纳入,直到 `contact_wake_max_bodies_per_tick` 或空闲醒体预算用完;放不下的组整组跳过;
- **落实**:被唤醒者当拍切为 Dynamic(零速度起步),按 §4.9 共同规则处理。

示例(默认 decay 0.5、门槛 1.0 kg·m/s):1 kg 方块以 5 m/s 撞进一排水平贴靠的冻结体。种子 p=5,
第 1 跳 2.5,第 2 跳 1.25,第 3 跳 0.625 低于门槛停止,共唤醒 3 个。

#### 4.10.4 补偿路径(预测漏掉的撞击)

撞击者在同一步内被别的碰撞加速后撞上冻结体,预测时看不到。补偿:`step` 之后从 rapier 接触对中收集
"Dynamic 实体 ↔ 冻结实体"且法向冲量合计 ≥ `contact_wake_min_momentum` 的对
(rapier 0.36 有 `ContactPair::total_impulse_magnitude()`),以该冲量为种子动量,在下一拍的 §4.10.3 中
一并传播。同一个冻结体有多对时取最大值。有一拍"撞墙"瑕疵,可自愈。待处理的补偿种子随快照保存。

**不计竖向接触**(修订 8 引入、修订 9 推广为双向,D21):一对接触中只要有一个接触流形的法向与竖直方向
足够接近——`|n · û| ≥ support_normal_min`(`û` = 重力反方向单位向量,法向口径同 §4.4.1 的支撑判定)——
这一对就不进补偿,不论冻结体在上还是在下。原因:竖向接触在静止时承载静压,不是撞击。
- 冻结体托着醒体(醒体在上):醒体每步产生 `m · g · dt` 的支撑冲量,随压着的质量增长(1 kg 方块约 0.16,
  8 kg 约 1.31,叠 7 个 1 kg 方块约 1.1),超过门槛后冻结体会被反复唤醒——醒、静止、冻结、又醒;
- 冻结体压在醒体上方(醒体在下,修订 9 补充):醒体被夹在地面和冻结体之间,rapier 在这类持久接触上
  报告的冲量持续偏高(实施方实测从 1.76 升到 11.9 后恒定),只按"冻结体是支撑方"单向排除时,冻结体
  同样被反复唤醒(05c 实施中 `acc_04b_closure_deferred_when_budget_short` 因此回归,总架构师复现确认);
- 改用"冲量突增量"也不行:冻结支撑者时会连带冻结压在上面的醒体(任务 04b 的叠放口径),醒体下一拍
  醒来,类型切换时突增量误判。

代价:竖直方向的撞击不进补偿。下落或上冲的撞击者撞前速度预测看得见;冻结体只在静止时冻结、本来就有
支撑,漏掉的代价只是少一点真实感。零重力不判定竖直方向,不排除任何一对;水平撞击 `n · û ≈ 0` 不受影响。

#### 4.10.5 不唤醒

方块/地形(共识 6,D9);待地形实体;观察者(非物理实体);其他分片的实体(§9.13)。

#### 4.10.6 为什么用接触图传播,而不用有限元

- 有限元求连续介质的应力场,要网格、刚度矩阵和稀疏线性求解。这里只回答"下一步谁会被波及",
  唤醒后的动量交换由 rapier 精确解算,有限元的精度用不上;
- 范围估大了,多醒几个实体,静止后撤票冻结,代价约 3 s 醒体预算;估小了,漏掉的一拍表现为"撞墙",
  补偿路径下一拍唤醒。廉价启发式足够;
- rapier 自己唤醒的就是整个接触岛,本方案是"有上限、按动量衰减的接触岛唤醒";
- 有限元真正有价值的地方是方块结构的受力与断裂,属于破坏/挖掘(IDEA-001)。

### 4.12 预算与优先级

- **阻塞请求**(D15):不装就有实体被卡住的 chunk 请求,包括:
  1. 待地形实体的当前足迹 ∩ 本分片区域内缺 ② 的 chunk(及其 ①);
  2. 被推迟唤醒的实体(含支撑闭包组的全部成员)当前足迹 ∩ 本分片区域内缺 ①/② 的 chunk;
  3. 待执行强制落地的实体中心柱缺 ① 的 chunk。

  阻塞请求由实体的当前状态推导,是请求属性,不是票种分支(不违反 §4.2.2)。它们**不受冷却门控**,
  但仍消耗该档预算。
- **chunk 候选排序键**(① 与 ② 各自):`(是否阻塞请求[阻塞在前], 票据优先级, 到锚点的距离, ChunkPos)` 升序,
  截断到该档预算。阻塞请求的"锚点"取被卡住的实体位置。
  卸载候选 = 已装载且不在任何 `Active`/`Paused` 票的"出"区域内、不被任何阻塞请求需要、**不在任何醒着
  实体的当前足迹内**、冷却已过者(卸载仍受冷却)。仅有观察者票且无阻塞请求时,退化为现状的"到最近观察者
  距离、ChunkPos"。
- **立足地保护**(修订 6,D19):醒着的实体(`Dynamic`)当前足迹内的 chunk 不作为卸载候选。这覆盖了
  "醒着、静止、在唤醒范围外、翻转冷却未过"这类没有任何票据覆盖其足迹的实体,避免脚下地形被卸载而违反 I2。
  判定只依据实体状态,不依据票种(§14 第 8 条同理)。冻结体和待地形实体不受保护(它们恢复前本来就会检查 ②)。
- **清醒预算**(`max_awake_dynamic`,每片):醒数超限 → 按到最近**唤醒中心**距离降序淘汰。唤醒中心 =
  带 `WakeSpec::Radius` 的 `Active`/`Paused` 票据的锚点(观察者票;带 ③ 档的区域票),不带唤醒范围的票据
  (例如只装载的区域票、实体运动票)不是唤醒中心(修订 6,D19)。淘汰顺序为距离降序(无唤醒中心 = +∞,同距 `EntityId` 升序)。被淘汰的**瞬态体 → 强制落地**,
  **常驻体 → 冻结并 `End ActorMotion`**(即便在运动中,属预算降级)。当拍因地形变更唤醒的实体不进淘汰池。
- 现有"命令唤醒同拍淘汰"路径(`enforce_budget_after_command_wake`)同规则。

### 4.13 分片 ensure 与生命周期

- **ensure**:每张 `Active`/`Paused` 票的 ① "进"区域内,每个 chunk 的 owner 分片必须已注册。
  观察者票另保留现状的 32 m 邻片 ensure,驱动侧不变;在途迁移信封的目的分片 ensure 不变。
- **保活**:分片有票 ⇔ 任一 `Active`/`Paused` 票的 ① "出"区域与该分片核心相交。观察者票按此规则即现状的
  "到 AABB ≤ 48 m"。
- despawn 条件仍为"空片 + 无票 + idle_expired"。瞬态体都会终结;承载静止冻结的瞬态体、冻结的常驻体
  仍会钉住分片,留作后续(D6)。

### 4.14 快照与回放

- 入快照:
  - **完整票据表**:键、规格(区域票的中心/半径/档位)、时钟、状态;
  - 票据收件箱中未到期的条目(由现观察者收件箱推广而来);
  - 每分片 ② 集合(恢复时据此重建 collider,而不是"凡 ① 皆建 ②");

  - ①/② 两套冷却簿记;
  - 待处理的接触唤醒补偿种子、待处理的地形变更唤醒格;
  - 未消费的 `ticket_ops`(随 outbox,沿用"快照携带未消费产出")。
- `CHECKPOINT_FORMAT_VERSION` **3 → 4**;旧档显式拒绝。
- 回放:区域票命令随外部命令日志重放;其余票据、待地形、强制落地、接触/地形变更唤醒由状态派生;

**观察者票与三档**

**瞬态体**

- **AC-T3 不悬空(蓝方块回归)**:观察者在原点,瞬态体水平抛出、落点距观察者 > 60 m。全程不冻结;落地凝固,

- **AC-T5 待地形**:人为让 ② 预算为 0(或测试钩子)使当前足迹缺 ②。实体进入待地形,位置不变、不穿地;

- **AC-T9 承载**:
  - 瞬态方块落在观察者范围外一个冻结常驻体上:不凝固;静止后冻结,票 `Suspended`;
  - 观察者靠近唤醒该常驻体时,支撑闭包同组唤醒方块;常驻体被推走后,方块下落、落地、凝固;

- **AC-T11 常驻运动票**:
  - 观察者附近的常驻体被推动后观察者立即移除:运动中不冻结,静止后才冻结,冻结时 y ≈ 地表;
  - 到达上限时撤票,计入 `actor_motion_capped`;
  - 唤醒后静止判据被重置:醒来后至少 `consecutive_ticks` 拍内不被判定静止。
- **AC-T12 支撑闭包**:一叠冻结实体(底层常驻体 + 上层常驻体/被承载瞬态体),唤醒底层 → 整叠同拍唤醒;
  空闲预算不足以容纳整叠 → 整叠推迟,无一单独醒来。
- **AC-T13 地形变更唤醒**:`SetBlock` 移除观察者范围外冻结常驻体脚下的方块 → 下一拍被唤醒并下落;
  醒体预算已满时仍被唤醒(当拍超限),之后按常规淘汰。
- **AC-T14 撞前唤醒的动量交换**:观察者范围外,1 kg 冻结常驻体静止在地面,1 kg 实体以 5 m/s 正面撞来。
  撞击那一步双方都是 Dynamic:被撞者获得明显速度(> 1 m/s),撞击者速度明显下降且没有反向弹回。
  对照组关闭接触唤醒时,撞击者被反弹、被撞者不动。
- **AC-T15 唤醒范围**:一排 5 个水平贴靠的冻结常驻体,撞击动量 p0 = 5 kg·m/s,默认参数下恰好唤醒 3 个。
  另验证:跳数上限生效;每拍上限与空闲预算截断生效且不淘汰已醒实体;多种子同拍时结果与处理顺序无关。
- **AC-T16 静止接触不唤醒**:醒着的实体静止地靠在冻结常驻体侧面 600 拍,不触发接触唤醒;醒着的重物
  静压在冻结体顶上(每步支撑冲量高于门槛)600 拍,同样不触发;冻结体压在醒体上方也不触发(修订 8/9,D21)。
- **AC-T17 补偿路径**:构造预测漏判的撞击(撞击者在本步内被第三方撞向冻结体)。下一拍被撞者被唤醒;
  补偿种子随 checkpoint 保存,恢复后行为一致。

**票据体系与转递**

- **AC-T18 区域票**:无观察者时 `SetAreaTicket`(①②③)让区域内 chunk 装载、范围内冻结体唤醒、

## 9. 语义变更与既有测试迁移清单

本 REQ **有意**改变以下行为。涉及的既有测试允许按此改断言,但需在提交说明中逐条对应:

1. "远处非 actor 实体被冻结"类用例(如 `sim.rs::frozen_body_ignores_detonate`、
   `frozen_body_excluded_from_solidify_and_migration`、`event_envelope_detonates_locally_frozen_immune`、
   `scheduler.rs::observers_drive_freeze_via_scheduler`、`activation.rs` 中的实体冻结/唤醒/超预算用例、
   `e2e/tests/activation.rs` 相关用例):把被测实体改为 `actor = true`,**并在期望冻结之前先让它静止**
   (例如零重力零速生成后推进 ≥ 21 拍,或落地沉降)。保留原意图,另补瞬态体的对应新用例。
2. 超预算淘汰用例:区分瞬态(强制落地)与常驻(冻结)。
3. `load_chunk` 同时建 collider 的用例:改为 ① 后 ②,或经测试辅助一次性两档就绪。
4. 快照格式与 `format_version` 相关用例:更新到 v4。
5. 观察者收件箱相关用例:推广为票据收件箱后,观察者命令语义不变,只允许改类型名/接口名。
6. 零重力凝固用例:不受凝固前提修订影响(零重力不判定支撑),断言不应改动。
7. **激活未启用模式下运行的既有用例**(§4.0):一律不得改动断言。

清单外的既有测试断言变动 = 回归,需说明理由并经验收方同意。
