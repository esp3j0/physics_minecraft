## 1. 背景与目标

现在世界里没有"身体":玩家只是一个移动的观察点(`MoveObserver`),实体只有方块和复合体。`actor` 标记和常驻票据
(REQ-007)是给未来的怪物、机械狗预留的,一直没有使用者。

用户的目标(2026-11-06):**玩家实体其实也是动物实体。未来强化学习的怪物、动物或者机器狗,要能导入进来,并且由模型控制。**

所以本需求不做"玩家"这个特例,而做一个统一的概念:**主体(agent)= 有身体、能接受动作的常驻实体**。玩家只是"身体 = 胶囊、
控制者 = 人"的一种组合。完成后要能走通这条链路:

> 导入一个四足机器人的模型 → 放进世界 → 在本项目的物理里训练策略 → 用模型控制它走路 → 它走在玩家炸塌的地形上;
> 玩家也能附身到它身上,用 WASD 指挥方向。

## 2. 核心模型

把"谁在控制"和"控制的是什么"拆开,共三层,再加一个观测:

```
控制者(确定性内核之外)              确定性内核(ShardSim)
┌─────────────────────┐   动作进输入日志   ┌──────────────────────────┐
│ 人(viewer 连接)      │ ─ 移动意图 ───┐    │ 行走控制器(单连杆身体)    │
│ 策略(ONNX,服务端推理) │               ├──► │ 或:意图 → 由策略转成关节目标 │
│ 外部训练器            │ ─ 关节目标 ───┘    │ 关节 PD 电机(多连杆身体)   │
│ 脚本(测试)            │                    └──────────┬───────────────┘
└─────────▲───────────┘                               │
          └──────────── 观测(纯函数读取本拍状态) ◄──────┘
```

### 2.1 身体 `BodyDef`

只读的数据资产,服务端启动时从 `assets/bodies/*.body.toml` 加载,按内容哈希标识。客户端只能按名字引用,不能上传。

- **连杆**:名字、质量、质心、惯量、碰撞形状(盒、球、胶囊、凸包,每连杆最多 8 个)、摩擦;
- **关节**:父子连杆、类型(`revolute` / `prismatic` / `fixed`)、轴、锚点、上下限、力矩上限、速度上限、PD 增益、默认角度;
- **自碰撞**:默认关闭,可按连杆对开启。相邻连杆接触一律关闭(`contacts_enabled(false)`);形状在关节处重叠是正常的,开着接触会造出假穿透(demo `gait`);
- **连杆树**:只支持树形,不支持闭环(闭环 URDF 拒绝导入,报告原因);
- **单连杆是退化情况**:玩家胶囊 = 1 个连杆、0 个关节,走同一套代码。

### 2.2 动作的两个层级

| 层级 | 命令 | 谁发 | 适用身体 |
| --- | --- | --- | --- |
| 意图 | `AgentIntent { move_xz, yaw, jump }` | 人、高层 AI | 所有身体 |
| 关节 | `AgentJointTargets { targets }`(目标角度,长度 = 非固定关节数) | 策略、训练器、脚本 | 多连杆身体 |

- 单连杆身体:内核里的**行走控制器**把意图转成水平力(有速度和力上限)与跳跃冲量(只在接地时生效)。靠力驱动,所以能被碎块推开。控制律、接地判定和接触钩子按 `capsule` 定值(§13)。
- 多连杆身体:意图不直接驱动关节,而是作为**策略的观测输入**,由策略输出关节目标。所以玩家附身机器狗时,WASD 是告诉策略往哪走。
- 非法动作(长度不符、NaN、超出关节范围)在进入内核前拒绝或钳制,计入遥测。**内核不信任模型输出。**

### 2.3 控制者

控制者运行在驱动层(`crates/app`),**不进确定性内核**。它产生的动作和玩家按键一样,都是带拍号的输入,写进输入日志。

这是本需求最重要的架构决定(D6):回放和检查点恢复只重放日志里的动作,不需要重新跑模型,REQ-001 以来的确定性保证不受神经网络影响。

| 控制者 | 动作来源 | 用途 |
| --- | --- | --- |
| `Human` | 连接发来的意图 | 玩家 |
| `Policy` | 服务端用 ONNX 推理 | 动物、怪物、机器狗 |
| `External` | 训练环境(§5.3) | 训练 |
| `Script` | 固定函数 | 测试、调试 |
| `None` | 无 | 电机保持最后目标 |

控制周期按身体配置,默认每 2 拍一次(30 Hz)。推理不阻塞 tick:超过一个控制周期没算完就沿用上一次的目标并记遥测,
实际生效的动作和拍号仍然进日志。

**附身**:玩家可以附身到任何主体。附身到策略控制的主体时,玩家只替换它的意图来源,策略继续运行。解除附身后回到观察者视角,
REQ-011 的调试工具继续可用。

### 2.4 观测

`ObservationSpec` 是一个纯函数,在控制周期从本拍末状态读取,可选项:机身系线速度与角速度、机身系重力方向、关节角度与速度、
上一次动作、足端接触、意图、周围地形高度采样。

地形采样半径受分片 margin 限制,保证跨分片时结果一致。观测向量的布局写进策略包(§5.2),加载时校验,不匹配就拒绝。

## 3. 身体与现有实体系统

- **实体身份**:一个主体只占一个 `EntityId`,所有连杆归它。`EntityRecord` 现在假定"一个实体一个刚体"(`rec.handle` 在 `sim.rs` 有约 78 处引用),
  主体的 `rec.handle` 指向根连杆,其余连杆放在新增的 `AgentRecord`。`collider_to_entity` 已支持多个碰撞体对应一个实体(复合体在用),连杆碰撞体同样登记。
- **关节形式**:rapier `MultibodyJointSet`(D3)。`snapshot.rs` 已包含 `multibody_joints`,但迁移路径和生成路径都没有。
- **常驻与票据**:主体 `actor = true`,豁免凝固和预算冻结,沿用 REQ-007 的常驻规则。预算计数按连杆数计。
- **观察者**:被人附身时,观察者位置跟随身体,服务端忽略该连接的 `MoveObserver`,防止客户端把视野和身体分开。
- **冻结**:无人观察、不持票的主体按 REQ-007 冻结,全部连杆一起冻结。**做法定为"快照 + 障碍物"(`freeze` demo,§13)**:
  - 冻结时记下和迁移相同的快照,移除整个 multibody;
  - 在原位留一个固定刚体,把每个连杆的碰撞体原样挂上去,保留各自的形状、相对位姿、摩擦和恢复系数;
  - 唤醒时移除障碍物,按快照重建主体。
  
  不能把连杆切成运动学或固定刚体:rapier 0.36.1 要求非根连杆必须是动力学刚体,切换后下一拍断言 panic(`multibody.rs:1457`)。只切根连杆不是冻结,其余连杆照样被求解、会漂移。
  实施时(B03)还要处理两件事:
  - 障碍物的碰撞体被接触或地形变化唤醒时,要映射回这个主体(REQ-007 的唤醒语义);
  - 冻结期间有方块放进障碍物所占的空间时,唤醒后会和主体重叠,要定处理办法。
- **迁移**:新增信封 `MigrateAgent`,带身体哈希、根状态、关节坐标、关节速度、最后的目标和控制者标识。**整个主体在同一拍原子迁移**,以根连杆中心判定归属。
  身体包络半径计入 REQ-001 §4.2 的 MARGIN 公式。
  - **重建**:按快照重建后,在下一次步进之前写回最后的目标,迁移那一拍照常步进。漏了这一步,主体会失力 1–2 拍(`migrate` demo,§13)。
  - **确定性**:同一世界历史加同一事件序列,重放逐位一致。不承诺迁移和不迁移的轨迹相同,也不承诺目标世界历史不同时轨迹相同。
  - **连杆顺序**:主体的行为与连杆在 rapier 活跃集里的顺序有关(§13"连杆顺序")。迁移和唤醒都会把顺序复位,这是预期行为,不需要在信封里保存顺序。
- **检查点**:格式版本 7 → 8,不做迁移,沿用"旧档显式拒绝"。
- **协议(只追加)**:`C2S::SpawnAgent`、`C2S::Possess`、`C2S::Unpossess`、`C2S::AgentIntent`、`S2C::AgentStates`(连杆姿态,与 `EntityStates` 分开发送,方块流不变)。

## 4. 质量比例(要求 demo 定值)

现在 1 格方块的质量恰好是 1(密度 1、体积 1),REQ-009 / REQ-010 的所有阈值都按这个单位标定,**不能改**。导入的机器人用真实单位(千克、牛·米),必须换算。

全部质量和力矩乘同一个系数 `k`,加速度不变,动力学不变。问题只在于 `k` 取多少。

**实现硬要求(demo `gait` 实证)**:PD 增益和 multibody 的默认阻尼也要乘同一个系数。rapier 给根节点转动和每个关节默认设了绝对常量阻尼 0.1,不随质量变化;不缩放的话,×0.01 档前进速度从 0.53 m/s 掉到 0.09 m/s。全部缩放后,质量比例在 10 到 0.01 之间动力学一致。

三种比例:

| 方案 | 1 格方块相当于 | 15 kg 机器狗的质量 | 单只脚(50 g)对方块的质量比 | 效果 |
| --- | --- | --- | --- | --- |
| 真实比例 | 约 1500 kg | 0.01 | 1 : 30000 | 真实,但求解器大概率不稳:方块压在狗身上会穿透或炸开 |
| **压缩比例(推荐)** | **100 kg** | **0.15** | **1 : 2000** | 方块很重、砸人有感,数值更可能稳定 |
| 不换算 | 1 kg | 15 | 1 : 20 | 稳定,但主体能踢飞方块,和世界观不符 |

系数放在配置里,全局一个值。**demo `mass` 已确认压缩比例 `k` = 1/100(§13)。** 重物可能让求解器发散,靠 §6 的失控防护兜底,不靠换 `k`。

## 5. 导入、策略与训练

### 5.1 导入身体

离线工具:`cargo xtask import-body <robot.urdf> --out assets/bodies/<名>.body.toml`。

- 先支持 **URDF**。MJCF 留作后续:很多现成模型只有 MJCF,但其语义更复杂;
- 自己写转换器(基于 `urdf-rs`),输出 `BodyDef`。`rapier3d-urdf` 0.36.1 与现用 rapier 同版本,可以参考,但直接生成 rapier 对象,不能得到可哈希、可迁移的数据;
  它的早期文档还写明忽略力矩和速度上限(当前版本未确认),这正是我们需要的字段;
- **碰撞形状**:基元直接转换;网格转凸包,并报告顶点数和体积偏差。不做凸分解;
- **视觉**:viewer 只画碰撞形状。不做贴图网格渲染,留给正式客户端;
- 工具输出**导入报告**:总质量、连杆数、自由度、被忽略的字段、被拒绝的元素。无效模型明确报错,不静默降级。

第三方模型文件在核实许可证之前不进仓库。CI 和冒烟用项目自带的手写四足身体(`assets/bodies/quadruped.body.toml`)。

### 5.2 策略包

```
assets/policies/<名>/
  policy.onnx      输入观测,输出动作
  policy.toml      身体哈希、控制周期、观测布局、动作缩放、默认姿态、归一化参数
```

推理用纯 Rust 的 `tract`(D7),只跑 CPU。加载时校验身体哈希、输入输出维度,任何一项不符都拒绝。

**用户需要知道的限制**:在 MuJoCo、Isaac 等其他仿真器里训练的策略可以按同样的格式导入,但**不保证能走**。这类策略通常按 200 Hz 物理训练,
而本项目是 60 Hz,接触模型也不同。可靠的路径是在本项目的物理里训练(§5.3),外部策略最多用作微调的起点。

### 5.3 训练环境

新增 `crates/agent-env`,进程内直接驱动 `ShardSim`,不走网络、不走 tick 节拍,跑的是和服务器**同一份物理代码**。

- Rust API:`reset(seed)`、`step(actions) → (obs, reward_inputs, done)`,一个环境可以有 N 个并行实例,各用独立线程;
- Python 层:PyO3 薄封装,提供 Gymnasium 风格接口。奖励函数写在 Python 这边,便于改动;
- 地形随机化:平地、台阶、炸出来的坑、散落方块,用现有的 `SetBlock` 和爆炸生成;
- 导出:训练完导出 ONNX + `policy.toml`,直接可部署。

训练只用 CPU:本机没查到 NVIDIA GPU,而 rapier 本身也只跑 CPU。按 §9.1 的探针粗算,16 线程约 2.5 万个策略步/秒,够训练平地行走,复杂任务会比较慢。

## 6. 主体与破坏系统的交互规则

默认规则(D8),目的是第一版的行为简单可预测:

| 情形 | 规则 |
| --- | --- |
| 主体碰方块、复合体 | 普通 rapier 接触,能推动也能被推动、被砸 |
| 主体作为撞击源 | **不触发**地形破坏和冲量流(REQ-010 §5.7、§5.8),走路和摔落都不破坏地形 |
| 复合体、方块撞到主体 | 按普通接触,主体不进复合体内部冲量流的汇点计算 |
| 爆炸 | 对每个连杆施加冲量,主体被炸飞,不受伤 |
| 地形承载 | 主体重量不计入承载判定(REQ-010 §4)。主体站上去不会压塌桥 |
| 脚下的桥塌了 | 主体正常下落 |
| **凝固、放方块与主体重叠** | **该格暂缓**,主体离开后再写入,计入遥测。否则主体会被埋进体素卡死 |
| 掉出世界 | 玩家身体回到出生点,AI 主体移除 |
| **失控** | 每拍步进后检查全部连杆,任一连杆速度超过 `V_GUARD`(暂定 200 m/s)或状态非有限,在下一拍之前按"掉出世界"处理,计入遥测。其他实体继续运行。没有这条,重物砸中主体时 rapier 可能 panic(§13) |
| 生命值、伤害、死亡 | 本需求不做 |

## 7. 非目标

- 生命值、伤害、背包、挖掘等玩法,以及动物的行为逻辑(觅食、寻路);
- 客户端预测与延迟补偿(第一版只考虑本机和局域网),正式客户端(#9);
- 贴图、网格、骨骼动画渲染;
- 闭环机构、软体、MJCF 导入;
- 主体之间跨分片的直接接触(沿用 REQ-001 §9.13,D11):分片边界上的主体会穿过邻片的碎块;地形接触不受影响;
- 账号与身份:断线后身体直接移除,重连是新身体(D12);
- 挖掘机(IDEA-001):等本需求完成后再评估,本需求解决了它依赖的关节组迁移;
- GPU 训练、在线学习(服务器运行时不更新模型);
- 主体改变物理步长或求解迭代的能力。全世界统一 60 Hz(D4),按主体追加迭代实际会改变整个分片(§13)。

## 8. 验收标准

### 阶段 A:单连杆主体与玩家

- [ ] **AC-A1 生成与生命周期**:经 `C2S::SpawnAgent` 生成的胶囊主体在静止 3600 拍后不凝固、不下沉、不被预算冻结;移除后不残留刚体和碰撞体。
- [ ] **AC-A2 行走**:`AgentIntent` 下胶囊在平地按设定速度行走,稳态速度误差不超过 5%;只有接地时能跳,跳跃能上 1 格台阶,上不了 2 格。
  跨 chunk 接缝行走(1.5、4.3、5.6 m/s,8 个航向)竖直速度峰值不超过 0.5 m/s、不卡住;站立 3600 拍漂移和下沉都不超过 1 cm。
  接缝钩子的 `dist` 要有单元测试:直接构造胶囊是 `collider1` 和 `collider2` 两种顺序、竖直间隙为正的接触,断言结果都等于竖直间隙(`capsule` 的整局对照行区分不出符号错误,§13)。
- [ ] **AC-A3 被物理影响**:方块砸中、爆炸、被复合体撞都会让主体产生位移;静止的主体不因为站着而破坏任何地形。
  质量 8、64、512 的整块从 5 m 砸下,扫落点(含擦边)并加高度微扰:无 panic、无 NaN,胶囊水平位移不超过 10 m(`capsule` 实测最大 6.08 m;摩擦方案错误时是 98 m,§13)。
- [ ] **AC-A4 不被埋**:主体占据的格不会被凝固或 `SetBlock` 写成实心,离开后暂缓的写入生效,最终方块总数守恒。
- [ ] **AC-A5 迁移**:行走中的主体穿过分片边界和四片交汇点,无跳变(相邻拍位移不超过速度上限的 1.5 倍)、不掉穿地形、控制不中断。

### 9.1 起草时的探针(仅供判断方向,不算 demo)

用 Python 绑定搭了一只 Go2 尺度的四足(约 15 kg,12 自由度,电机 kp 20、kd 0.5,力矩上限 23.7),固定目标姿态站立 5 秒,期望机身高度约 0.33 m:

| 关节形式 | 物理频率 | 求解迭代 | 机身高度 (m) | 高度标准差 (m) | 机身 up 最小值 | 每帧耗时 (ms) |
| --- | --- | --- | --- | --- | --- | --- |
| multibody | 60 Hz | 4 | 0.347 | 0.0006 | 0.993 | 0.26 |
| multibody | 120 Hz | 12 | 0.338 | 0.0000 | 0.998 | 1.07 |
| multibody | 240 Hz | 4 | 0.358 | 0.0000 | 0.999 | 0.91 |
| 普通关节 | 60 Hz | 4 | **0.164** | 0.0043 | 0.984 | 0.06 |
| 普通关节 | 240 Hz | 12 | **0.262** | 0.0007 | 0.968 | 0.41 |

读法:

- multibody 在 60 Hz 下能站稳,不发散。普通关节塌得多:60 Hz 只有 0.14–0.23 m,240 Hz 也只到 0.24–0.30 m。这是 D3 的依据;
- multibody 的高度随参数在 0.30–0.38 m 之间变化,跟踪并未收敛。站得住不等于走得好;kp 60、kd 2 的组合在 60 Hz 下还有明显抖动(标准差 0.013);
- **没有测行走**:这个 Python 绑定没有找到运行时修改 multibody 电机目标的入口(`Multibody` 和 `MultibodyLink` 都不暴露关节数据),所以只测了固定目标。这正是 demo `gait` 必须用 Rust 做的原因;
- 耗时是单只、单线程、Python 调用的粗略数字,当时机器还在跑其他任务。

- **相邻连杆接触关闭**(§2.1)。真实几何下关闭后站立和行走都正常;
- **力矩上限生效**:同组把上限降到 12 / 6 / 3 N·m,饱和占比升到 25% / 62% / 82%,速度降到 0.23 / 0.01 / 0.00 m/s。23.7 下饱和占比几乎为 0(全矩阵最高 1.3%);
- **开环走不直**:航向对参数非常敏感,相近参数下净位移差很多(同组 kp 100 kd 3 换脚摩擦 1.4 后沿航向 0.228、净位移只有 0.049),所以判据看沿航向的速度。走直是策略阶段的事;
- **耗时**:单只每拍 P95 约 0.15 ms(机器空闲,含采样);同世界 8 只 P95 1.2–1.4 ms(空闲重跑),交付时机器繁忙测得 2.09 ms。都是裸 rapier 平地,不含生产路径开销。

| 末态 | 不再发散 | 133 组站回,58 组倒地,59 组蹲低 |

**这些结果对落点和高度很敏感**:只测一组 d0 网格时峰值是 19.9 m/s,加几厘米高度微扰就到 68.3 m/s。撞击类测试必须扫落点并加微扰。

重物(整块立方体,质量 8、64、512,5 m 落下,每格 45 组,无防护;格内是 panic 次数 / 未 panic 组的连杆峰值 m/s):

| --- | --- | --- | --- |
| 1/100 | 0 / 126 | 2 / 3.6×10¹⁷ | 4 / inf |
| 1/20 | 0 / 57 | 0 / 67 | 3 / 6.3×10¹⁸ |
| 1/5 | 0 / 16 | 0 / 74 | 0 / 79 |
| 1 | 0 / 3.9 | 0 / 11 | 0 / 51 |

- **防护**:每拍步进后查全部连杆,速度超过 `V_GUARD` 或状态非有限就处理这只主体(§6)。矩阵里 14 次 panic 的前一拍都还有限,线速度都不低于 2204 m/s,所以防护来得及。V = 200 和 1000 下全部 2835 行 0 panic、0 NaN,世界继续运行。没有误杀:V = 200 时质量 8 实测 0 移除(峰值 126 m/s),单格方块峰值 68.3 m/s 也低于阈值;
- **重物的静置穿透不设门槛**:质量 64、512 砸中后,不爆炸的组也常超过 5 cm,最深 30 cm。这是压在身上的物理结果,交给玩法层;

- 自然睡眠时不动,所以空闲 AI 不受影响;
- 策略控制靠闭环修正。`learn` 要确认它不妨碍训练。如果妨碍,再带数据讨论全局 PGS;
- 全局 PGS 2 能压到 0.0004 m/s,但平地走速降到约 84%,而且生产测试有 6 条变红(静止叠放、跨分片一致性等,根因没有逐条查),所以现在不改。

**按主体追加求解迭代:不采用。** rapier 文档写着只影响连通分量,实际上世界里只要有一个 multibody,所有醒着的刚体都合成一组求解(`rapier3d-0.36.1/src/dynamics/solver/staged_island_solver/init.rs:62`)。实测主体 extra 12 时,20 m 外方块堆的哈希与全局 16 迭代逐位相同,堆的平均高度从 1.20 m 变成 1.50 m。按主体加 PGS 同理。

普通关节版本(impulse joint)隔离成立,但机身塌到 0.15 m,走不动,D3 不变。

### `migrate`(通过,2026-11-07,`demos/agents/migrate/`,提交 819540a)

**结论:按快照重建 multibody 不跳变、不摔倒,接触缓存丢了也没有影响。迁移前后速度差异来自连杆顺序,和迁移本身无关。**

- **重建误差**:186 个完整快照迁移行,关节坐标、连杆位置、姿态误差都逐位为 0。比较的是读回的关节角和刚体位姿;
- **单次迁移**:12 个步态相位,平地和 chunk 接缝两种地形,同世界和跨世界的速度都是同相位不迁移对照的 99.9–100.7%,全程不摔。迁移后 120 拍:up·y ≥ 0.989,\|vy\| ≤ 0.284 m/s,机身相邻拍位移 0.0107 m(与对照相同);
- **落地那一拍迁移**:各项不差于不迁移的落地对照;
- **来回迁移**:每 30 拍、每 120 拍各一次,速度都是同窗口对照的 100%。每 5 拍一次是 94%,每 2 拍一次是 69%,但不摔;
- **不带速度**:步行时速度只差 0.1%。信封仍然带速度,给落地和高速工况用;
- **8 只同拍迁移**:平均 57 µs/只,窗口指标与 8 只不迁移对照同量级;
- **重放**:全矩阵 331 行双跑逐行相同。

**第一轮的大幅掉速是实现漏洞,不是物理现象**:重建后没有写回目标,迁移那一拍也没有步进。修正后,每 2 拍迁移一次的速度从 0.0057 m/s 回到 0.3692 m/s。见 §3"重建"。

**已知缺陷(不影响结论,记录在案)**:`pilesleep` 组推迟迁移时每次只顺延 1 拍,12 个相位最后在同一拍迁移(哈希相同),所以这组只相当于一个相位。统计窗口在未迁移时也会收进名义窗口的拍,这组的机身相邻拍位移(T1 最大 0.147 m)是跨段拼接的假值;落地组推迟后已不是"落地那一拍迁移"。这组的有效结论只有一条:目标世界的方块堆真的睡着时,迁移后的速度是干净世界的 100.2%(T0)、100.4%(T1)。

### `freeze`(通过,2026-11-07,`demos/agents/freeze/`,提交 819540a)

**结论:冻结用快照加障碍物(§3)。把连杆切成运动学或固定刚体都不行。**

| 方案 | 结果 |
| --- | --- |
| 全部连杆切运动学 / 固定 | 下一拍 panic(`multibody.rs:1457`:非根连杆必须是动力学刚体) |
| 只切根连杆(运动学 / 固定) | 不 panic,但其余 12 个连杆照样被求解:冻结期间漂移最大 0.27 m / 0.41 m,固定方案 12 行唤醒后摔倒。不算冻结 |
| **快照加障碍物** | 冻结期间障碍物位移逐位为 0,被方块砸中也一样;碰撞体逐个核对相符(含材质);唤醒误差逐位为 0 |

快照加障碍物的数据:
- **唤醒后表现**:站立和 12 个相位行走,恢复速度和清零速度两种唤醒方式,唤醒后 120 拍 up·y ≥ 0.981、\|vy\| ≤ 0.244 m/s、机身升高 ≤ 1 cm,全程不摔。行走速度是对照的 97.0–99.9%;
- **长冻结**:冻结 3600 拍和冻结 600 拍的结果逐项相同;
- **耗时**:单只冻结 44–66 µs,唤醒 36–62 µs。8 只同拍冻结 52 µs/只,唤醒 37 µs/只;
- **布景**(只报结果):
  - 压住:冻结前 30 拍放 1 格方块,机身被压到约 0.14 m,唤醒后方块仍在背上;
  - 砸中:冻结后第 100 拍方块落到障碍物上,唤醒后主体被方块压低到约 0.06–0.11 m,方块仍在背上;
  - 半空冻结:唤醒后才落地;
  - 移走脚下方块堆:唤醒时主体在 1.27 m 高处,唤醒后第 27 拍触地,随后翻倒。
- **重放**:全矩阵 88 行双跑逐行相同。

### `capsule`(通过,2026-11-07,`demos/agents/capsule/`,提交 5d81f80)

**结论:力驱动的胶囊控制器可用。推荐参数 τ 0.2 s、F_max 8·m·g、μ 0.3、空中力系数 0.2、跳高 1.4 m、接地容差 0.05 m、球投射接地判定。** 胶囊 `capsule_y(0.6, 0.3)`,质量 0.8,锁转动。第一版和第一轮返修各被退回一次,前两次的问题都是实现问题,不是控制律或地形的固有限制。

| 判据 | 结果 |
| --- | --- |
| 平地稳态误差 ≤ 5%(大平面和 chunk 地形,三档速度 × 8 航向) | 0.00–0.15% |
| 1 格台阶跑动、静止起跳各 10/10;2 格 0/10 | 1 格全 10/10;2 格全 0(顶点 1.39 m) |
| 空中连按跳不高于单次跳 + 2 cm | 逐位相同 |
| 站立 3600 拍漂移、下沉 ≤ 1 cm | 都是 0,入睡 |
| 跨 chunk 接缝竖直速度峰值 ≤ 0.5 m/s | 0.0143;关掉接缝钩子是 0.22 / 1.39 / 1.82 |
| 单格方块砸中:无 panic、无 NaN、有位移 | 125 组通过,位移最大 0.62 m |
| 全矩阵双跑 | 3120 行逐行相同;独立重跑与提交逐行相同 |

**后续实现要用到的结论:**

- **控制律**:`F = clamp(m(v_t − v)/τ, F_max)`,空中乘空中力系数;决策 30 Hz、施力 60 Hz。rapier 0.36.1 的 `add_force` 不会自动清零,每拍施力前要 `reset_forces`;
- **摩擦**:胶囊用默认 Average 合成,在接触钩子里把**胶囊对固定刚体的每个流形**的摩擦设为 0(地面和墙面都包括),对动态方块保留摩擦。不清零时 μ 和地面 0.6 合成后有 τ·μ_eff·g 的稳态误差,撞台阶侧面还会吃掉起跳的竖直速度。**不要用 `CoefficientCombineRule::Min`**:胶囊对方块也没有摩擦后,质量 512 的整块擦边砸中会把胶囊横向挤出 98 m,速度 116 m/s;按现在的方案是 6.08 m、10.6 m/s。μ 只决定胶囊对方块的摩擦,0、0.3、0.6 三档差别很小;
- **接地判定**:射线只测中心一点。整个胶囊从贴地位置向下 `cast_shape` 不可靠(1500 拍里 614 拍不命中,481 拍法线水平)。改为从下半球球心上方 5 mm 向下投一个半径 r − 0.02 的球,稳定命中;
- **接缝钩子**:跨 chunk 边界时,下一个 chunk 碰撞体的顶边进入预测距离,产生倾斜约 17° 的推测接触,5.6 m/s 时把胶囊弹起 vy ≈ 1.8。用 `PhysicsHooks::modify_solver_contacts` 处理:只看胶囊对固定刚体、|n.y| 在 [0.7, 1) 内、接触点都在胶囊底部 ±3 cm 以内的流形,把法线摆成竖直,`dist = 竖直间隙.max(原 dist.min(0))`。**竖直间隙不乘法线符号**;胶囊是 `collider1` 时法线朝下,乘了符号会把间隙当成穿透。共面接缝处竖直间隙接近 0,所以先插胶囊、后建地形的整局对照行(胶囊全程是 `collider1`)区分不出这个错误,只有穿透从 −0.0002 m 变成 0;符号要靠单元测试守住(AC-A2);
- **内核要带钩子步进**:摩擦清零和接缝修正都在钩子里,生产步进要改用 `step_with_events(&hooks, ..)`,只给主体碰撞体设 `ActiveHooks::MODIFY_SOLVER_CONTACTS`。世界里没有主体时钩子不触发,AC-A8 要验证 golden 轨迹不变;
- **重物**:单刚体胶囊被质量 8、64、512 的整块砸中都不 panic,`V_GUARD` 200 下 0 次触发。摩擦方案错误时位移会很大,所以 AC-A3 给重物加了位移上限;
- **连杆顺序**:单刚体没有连杆顺序效应,在主体之前插入 16 个会睡着的刚体,速度逐位相同。

**已知局限(不影响结论)**:推方块的位移与 τ 的关系没有做单变量对照,未归因;方块堆两列 `pile_land_*` 是全程最深穿透和第 60 拍起的竖直速度峰值,不是逐拍定位的落地那一拍;接缝场景的出生点和 T1 行走相同,开钩子的行与 T1 行走逐位相同,有效对照是关钩子的行。

### 连杆顺序(`migrate` 验收发现,2026-11-07)

**同一个开环步态,只因主体的连杆在 rapier 活跃集里的顺序不同,速度和航向就会大幅变化,和接触、距离都没有关系。**

**机制**:刚体入睡时,`island_manager/manager.rs:95` 用 `swap_remove` 把它移出活跃集,把末尾的刚体搬到它的位置。在主体之前插入、后来睡着的刚体,会把主体的连杆一根根搬到前面。求解顺序变了,1 次 PGS 下足以改变步态。

T0 平地,主体直接出生,1320 拍:

| 世界内容 | vfwd(m/s) | 全程航向变化 | 连杆顺序(机身记 B) |
| --- | --- | --- | --- |
| 干净世界 | 0.5161 | −21° | `B-1-2-…-12` |
| 主体之前插入 1 个会睡着的方块 | 0.4326 | +440°(绕圈) | `12-B-1-…-11` |
| 之前插入 4 个 | 0.3392 | −62° | `12-11-10-9-B-1-…-8` |
| 之前插入 ≥ 13 个(13–64,含 200 m 外) | 0.2879–0.2880 | −146° 左右 | 完全倒序 |
| 之前插入 4 / 16 个无碰撞体刚体 | 0.3379 / 0.2878 | 同数量方块 | 同数量方块 |
| 之前插入 64 个固定刚体、16 个出生就睡着的刚体,或插在主体之后 | 0.5161–0.5164 | −18° – −21° | 不变 |

- **重放仍然逐位确定**,但同一个策略在不同分片、不同时刻的表现可能不同;
- **顺序可以是任意排列**:一批刚体在同一拍入睡时,会出现 `10-B-8-1-4-7-12-6-5-2-9-11-3` 这样的打散排列;
- **重建会复位**:迁移或唤醒重建后,主体排到活跃集末尾,顺序回到 `B-1-…-12`;
- **对后续阶段的要求**:`learn` 必须用打乱的顺序评估策略(§9);AC-B2 要在打乱顺序下也满足;以后比较两组行走速度之前,先对齐连杆顺序,不要把差异归因到迁移、冻结或地形。
